Why this setup

Claude Code takes on long-running work, but in a default terminal the session is tied to the window. Close it or lose the SSH link and the server, tests and git view beside the conversation go with it. Step away and there is no way to pick the session up from a phone or another PC.

Detach sessions from the window

A multiplexer (psmux) or Claude Code’s agent view keeps work running after the window closes.

Several views at once

Claude, the server and git side by side — and Claude can read errors from the next pane itself.

Resume from anywhere

Remote Control continues the same session from a phone or browser.

macOS-style muscle memory

Aliases such as y, z, ll and lg work the same on Windows.

Recommended setup: keep what you have, add three layers

There is no reason to replace the terminal or the shell. Windows Terminal is updated steadily and ships with the PC. What is missing is sessions bound to a window and a way to resume remotely; the layers below fill exactly that.

  • psmux is optional. If you only need sessions to stay alive, agent view (claude --bg) does it. For PCs where psmux is not an option, the Windows Terminal-only way is described below.
  • Moving to WSL2 is only worth it when you really need the Claude Code sandbox. Agent teams split views work natively inside psmux.
  • WezTerm has good external control but its stable release stalled in February 2024, so it is left out. Ghostty has no official Windows build.
  • This setup still gives you no screen rewind, no inline images and no iTerm2-style SSH file transfer.

Usage tips

Pick what you need once setup is done. Tips that require editing a config file are marked after setup; the config snippets will live in the install guide when it exists.

Getting more from psmux
  • Open yazi in the next pane after setup — One added key binding makes Ctrl+b → Tab open yazi for the current folder in a right-hand pane. Quitting with q closes the pane.
  • One script for a project layout after setup — A script builds the Claude, server and git panes instead of splitting by hand. If the session already exists it just attaches.
  • Hand a neighbouring pane’s error to Claude — Name the server pane with Ctrl+b → T, then ask “read the last 50 lines of the server pane and explain the error”. Claude reads it with psmux capture-pane -p -t main:1.2 and can send commands to another pane with psmux send-keys. main:1.2 means session:window.pane.
  • One session per project after setup — Names like tm api and tm web keep separate sessions and layouts. Switch with Ctrl+b → s.
  • Lost among panes — Ctrl+b → q shows numbers to press, or Ctrl+b → w shows everything as a tree. Zoom a narrow pane with Ctrl+b → z.
  • Cross-check with several AIs check policy — Open agents such as Codex CLI or Gemini CLI in other panes, send the same question and have Claude combine the answers. Each CLI needs its own install and login. On a company- or institution-managed PC, first check that external AI tools are allowed — your code goes to each vendor’s servers.
  • tmux commands work too — Installing psmux also provides tmux and pmux names, so tmux commands and scripts from macOS or Linux run unchanged.
Shell and tools
  • Pass an error to Claude after setup — Right after a failed command press Ctrl+Shift+↑ → Ctrl+C → Ctrl+V in the Claude prompt. No dragging needed (the shell has to mark command boundaries). unconfirmed inside psmux
  • Pass a file path to Claude — Select a file in yazi, press c c to copy its path and paste it after @ in the Claude prompt.
  • Review what Claude changed — Keep lg open in another pane and changed files show up at once. Press Enter to pick lines and commit; z undoes the last git action (it cannot undo a commit you already pushed).
  • Re-run earlier commands — Type the first few letters and press F8, or press Ctrl+R and type part of a word.
  • Land in the folder you left yazi in after setup — A small shell function moves you to the last folder when you quit with q; Q quits without moving.
  • fzf·ripgrep — Install them separately and three searches come alive: zi (pick a folder), yazi z (file jump) and yazi S (content search).
  • Teach zoxide your folders — Right after install z knows nothing. zoxide add D:\work\my-app makes z my-app work at once; zoxide remove path forgets a wrong one.
  • Folders as a tree — eza -T -L 2 shows two levels as a tree; ll -T -L 2 adds git status.
Long jobs and remote access

Hand long jobs — builds, migrations, AI agents — to a named session and detach. Next day run psmux ls then psmux attach -t name.

  • Close RDP with the ✕ at the top right (disconnect). Signing out from the Start menu may lose the session.
  • Different resolutions per client shake the pane ratios. Zoom with Ctrl+b → z or fix the Windows Terminal start size.
  • Over SSH the mouse works with plain ssh when the server is Windows 11 build 22523 or later. On a Windows 10 server only the keyboard works.
psmux mouse — unlike tmux

tmux ships with the mouse off; psmux has it on. Click a pane to focus it, drag borders to resize, click a window name in the status line to switch, scroll with the wheel, drag to select (release copies to the clipboard) and right-click to paste. Hold Shift while dragging to use the terminal’s own selection. Turn it off with set -g mouse off.

Without psmux

For PCs where psmux is not available: run several Claude sessions side by side in Windows Terminal panes. Closing the window ends the sessions, so keeping them alive is agent view’s job (claude --bg).

Building a 2×2

  1. In a new tab, go to the project folder and run claude.
  2. Alt+Shift+＋ → in the right pane run claude --worktree my-app-2.
  3. Alt+Shift+− → in the lower right run claude --worktree my-app-3.
  4. Alt+← to go left, then Alt+Shift+− → in the lower left run claude --worktree my-app-4.

Why worktrees — Two sessions in one folder share the working tree and git index, so uncommitted changes get mixed up. claude --worktree name creates a separate checkout in .claude/worktrees/name/ on a worktree-name branch. If you use Dandi it has a naming rule — see “With Dandi” below.

Using it with Dandi

  • Keeping sessions alive: Dandi’s doc 01 §D recommends agent view before a multiplexer. psmux is an optional layer on top.
  • Worktree names: Dandi numbers them like .claude/worktrees/NNN-summary and finds them with /resume NNN. The my-app-2 in the 2×2 example above, or the automatic names from agent view, carry no number and cannot be found that way.
  • Concurrent agents: Dandi’s agent-guard limits parallel subagents to what the PC can take. Whether agent teams teammates opened as panes count toward that limit was not confirmed.
  • Windows check-up: the Windows Terminal default profile, PATH and Git are diagnosed by Dandi’s /win-setup. This page does not repeat that — see the skill catalog.
  • lazygit: installation and diff-tool setup are covered by §16 in the options dictionary. This page only covers using it.
