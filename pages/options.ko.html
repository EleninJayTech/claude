0. 먼저 알아둘 낱말 8개

이것만 알면 아래 선택지가 전부 읽힙니다

낱말뜻
드롭인 문서 “폴더에 던져넣고(drop in) 한 문장 말하면 알아서 적용되는 설명서”. 이 저장소의 00~06 파일들이 그것입니다. 프로그램이 아니라 Claude가 읽고 따라 하는 글이라, 설치라고 해도 결국 설정 파일 몇 개를 만드는 일입니다.
스코프(scope) 설정이 어디까지 적용되는지의 범위. 글로벌 = 내 PC의 모든 프로젝트(~/.claude/에 저장). 프로젝트 = 이 폴더 하나(<프로젝트>/.claude/에 저장, git에 커밋하면 팀원도 같이 씀). 선택지에서 “스코프를 고르라”는 건 나만 쓸지 팀도 쓸지를 묻는 겁니다.
settings.json Claude Code의 설정 파일. 주로 권한을 적습니다 — allow(묻지 말고 실행) · ask(실행 전 물어봄) · deny(아예 금지). 예를 들어 deny에 .env를 넣으면 비밀번호 파일을 읽으려는 시도가 차단됩니다.
훅(hook) “이런 일이 생기면 이 명령어를 자동 실행하라”는 규칙. 이 문서에서 쓰는 건 대부분 PostToolUse — Claude가 파일을 고친 직후 린트나 문법 검사를 자동으로 돌립니다. 에러가 나면 그 출력이 Claude에게 되돌아가서 스스로 고칩니다.
스킬(skill) / /명령 SKILL.md라는 마크다운 파일 하나가 곧 /이름 슬래시 명령이 됩니다. 예: skills/resume/SKILL.md를 만들면 /resume를 칠 수 있습니다. 내용은 “이럴 땐 이렇게 해라”라는 지시문입니다.
서브에이전트 메인 대화와 별도의 작업창에서 도는 보조 Claude. .claude/agents/이름.md로 정의하며, 에이전트마다 다른 모델을 지정할 수 있습니다. 어려운 분석은 비싼 모델, 반복 작업은 싼 모델 — 이게 02 문서의 핵심입니다.
MCP Model Context Protocol. Claude에 바깥 도구를 꽂는 규격입니다. GitHub·브라우저·문서 검색 같은 걸 연결해 Claude가 직접 쓰게 만듭니다. USB 포트라고 생각하면 됩니다.
effort(추론 강도) “얼마나 깊이 생각할지” 조절하는 값. low → medium → high → xhigh → max. 높이면 어려운 설계 판단이 좋아지고, 대신 토큰(비용)과 대기 시간이 늘어납니다. 모델 선택과는 별개의 축입니다.
💡 “토큰을 아낀다”는 말이 자주 나오는 이유 Claude는 주고받은 글자 수(토큰)만큼 요금제 사용량을 씁니다. 그래서 이 문서들은 1순위 = 최적의 결과물, 2순위 = 품질을 해치지 않는 선에서의 절약이라는 원칙을 공유합니다. 절약하겠다고 검증·기록·어려운 작업의 상위 모델을 빼지는 않습니다.

1. 질문은 어떤 순서로 나오나

조사 먼저 → 큰 선택 → 문서별 세부 선택

Claude는 질문하기 전에 먼저 조사합니다. 이미 설치된 게 있는지, git 저장소인지, 어떤 언어를 쓰는지 등을 파일로 확인한 뒤, 코드로 알 수 없는 것만 물어봅니다. 그래서 실제로 받는 질문은 생각보다 적습니다.

단계하는 일사용자가 고르는 것
STEP 1설치에 필요한 문서(01~06) 확보 — 같은 폴더에 없으면 GitHub에서 가져옴없음
STEP 2환경 감지 — 이전에 적용한 기록(dropin-applied), 기존 설정 파일, 프로젝트 유형 조사없음
STEP 3큰 선택 — 아래 §2의 5가지 질문기반 모드 · 목적 번들 · 운용 프로필 · 산출물 언어
STEP 4고른 문서의 절차대로 설치. ‘사용자’ 모드일 때만 문서 안 세부 항목(§3~§8)까지 추가로 물어봄모드에 따라 다름
STEP 5검증하고 결과 보고 + CLAUDE.md 맨 아래에 적용 기록 한 줄 남김커밋 승인
📌 ‘사용자’ 모드가 아니면 세부 질문은 생략됩니다 최소·권장·전체 모드를 고르면 문서 안의 세부 항목은 모드가 정한 기본값으로 자동 확정됩니다. 즉 아래 §3~§8은 “직접 고르고 싶을 때 읽는 부분”이자, “자동으로 뭐가 켜지는지 알고 싶을 때 읽는 부분”입니다. 다만 안전 질문(이미 있는 걸 덮어쓸까요? 회사 정책은 확인했나요?)은 어떤 모드에서도 생략되지 않습니다.

2. 맨 처음 공통 질문 5가지

여기만 답하면 설치가 굴러갑니다

2-1. 적용 대상 — 이 PC인가, 이 프로젝트인가

모호할 때만 물어봅니다. PC를 고르면 ~/.claude/(내 계정 폴더)에, 프로젝트를 고르면 지금 폴더의 .claude/에 설정이 만들어집니다. 보통 처음 한 번은 PC 설정을 하고, 그다음부터는 프로젝트별로 합니다.

2-2. 기반 모드 — 넷 중 하나 (단일 선택)

최소01만

기록 체계와 보안만 깝니다. 문서 안 세부 항목도 필수만.

생기는 것
글로벌 settings.json(보안 잠금), /resume·/wrap·점검 스킬(/dropin-check·/dropin-update), 프로젝트 docs/ 3종
이럴 때
코드가 없는 문서 저장소, 혹은 “일단 기본만 써보고 싶다”
권장기본 추천상황별 자동 조합

감지 결과에 따라 Claude가 알아서 조합하고, 왜 그렇게 골랐는지 한 줄로 보여줍니다.

규칙
새 PC → 01(글로벌)+03(HUD) / 개발 프로젝트 → 01+02+04 / 문서·비개발 저장소 → 01만 / 이미 01이 깔린 곳 → 아직 없는 것 중 필요한 것만
이럴 때
대부분의 경우. 잘 모르겠으면 이걸 고르면 됩니다
전체01~06 전부

해당 없는 것(예: 코드가 없는 저장소의 02)은 빼고 알려줍니다.

주의
“전체”여도 이미 있는 설정을 말없이 덮어쓰지는 않습니다 — 유지/재구성/교체를 매번 물어봅니다
이럴 때
새 프로젝트를 제대로 세팅하고 싶고, 질문에 답할 시간이 있을 때
사용자2단계 직접 선택

문서를 고르고 → 그 문서 안의 항목을 또 고릅니다. 아래 §3~§8이 전부 질문으로 나옵니다.

이럴 때
필요한 것만 딱 집어서 넣고 싶을 때. 이미 한 번 설치해봐서 구조를 아는 경우

2-3. 목적 번들 — 0개 이상 (복수 선택)

기반 모드 위에 합집합으로 더해집니다. 예를 들어 ‘권장’ + ‘디자인’을 고르면, 권장이 고른 것에 디자인 관련 확장이 얹힙니다.

번들얹히는 것언제 자동으로 체크되나
디자인
웹 퍼블리싱		03의 svg-design(SVG 시각효과 규칙) · frontend-design(AI 티 안 나는 UI) · 브라우저 검증(만든 화면을 Claude가 직접 열어 확인)프론트엔드 스택이 감지되면 기본 체크
검증 강화04 전부 — 훅 품질 게이트 + gh/glab CLI + CI 통합테스트·CI 설정이 감지되면 기본 체크
무인 자동화06 클라우드 루틴 (+04 CI 병행 권장)감지 불가 — 직접 요청할 때만
회사새로 설치되는 건 없음. 안전장치를 조이는 수정자입니다 — CI는 조직 정책 확인 필수, MCP는 허용된 서버만, 루틴은 조직 승인 필수“회사 저장소예요”라고 답하면 자동 적용
응답 스타일05 출력 스타일감지 불가 — 직접 요청할 때만

2-4. 운용 프로필 — 표준 / 절약

표준기본

품질 우선. effort 기본값을 그대로 두고, 어려운 작업엔 상위 모델을 씁니다.

절약Pro 요금제 · 한도 관리

사용량 한도를 신경 써야 할 때. 다만 깎는 건 기본값과 낭비뿐입니다.

바뀌는 것
세션을 /effort medium으로 시작 · 서브에이전트를 Sonnet 중심으로 배정 · 로스터 축소 · claude-hud를 기본 체크(사용량이 보여야 아낄 수 있으니까)
안 깎는 것
난이도 분류 · 최종 리뷰 · 검증 게이트. 여기서 아끼면 재작업이 더 비쌉니다

2-5. 산출물 언어 — 한국어 / English

문서 언어가 아니라 생성물 언어입니다. 이 저장소의 드롭인 문서(00~06)는 한국어지만 Claude는 어느 언어로든 똑같이 실행하므로, 번역본은 없습니다. 대신 이 질문이 설치가 만들어 내는 것들의 언어를 정합니다.

언어기본 = 대화 중인 언어

답한 언어로 대상 CLAUDE.md 본문 · docs/ 기록 항목 · 커밋 메시지 · 산출물 파일명이 만들어집니다.

파일명도 바뀐다
docs/난이도-매트릭스.md ↔ docs/difficulty-matrix.md, docs/핸드오프-규약.md ↔ docs/handoff-protocol.md. 이미 다른 이름으로 있으면 그 이름을 그대로 둡니다
안 바뀌는 것
형식 키워드 — [갈래][Done]·dropin-applied 같은 표시는 언어와 무관하게 고정입니다. /resume·/wrap·검사 스크립트가 그 문자열로 찾기 때문입니다
기존 기록이 있으면
그 언어를 우선합니다 — 한 파일 안에서 언어가 섞이면 /resume이 읽는 기록이 갈립니다
남는 자리
적용 기록에 언어=ko 또는 언어=en으로 남아 재적용 때 유지됩니다

2-6. 이미 설치돼 있으면 — 유지 / 재구성 / 교체

기존 설정이 감지된 항목마다 따로 물어봅니다. 모드와 상관없이 항상 물어봅니다.

  • 유지 — 건드리지 않고 건너뜁니다. 잘 쓰고 있다면 이것.
  • 재구성 — 어긋난 부분만 맞춥니다. 기존 걸 살리면서 새 버전 내용을 반영하고 싶을 때.
  • 교체 — 기존 걸 지우고 새로 만듭니다. 예전에 대충 만들어둔 걸 정리할 때.

3. 01 기본 셋업 — 기록 체계와 보안

ⓐ~ⓕ 여섯 항목 (복수 선택 · 전부 기본 체크)

이 문서가 하는 일은 “어제 뭐 했더라”를 없애는 것입니다. 작업 기록을 파일로 남기게 하고, 다음 세션에서 /resume 한 번으로 이어가게 만듭니다. 여기에 시크릿 보호가 얹힙니다.

ⓐ글로벌 행동 규칙기본 체크

“추측하지 말고 물어봐라”, “요청한 것 이상 만들지 마라” 같은 Claude의 작업 습관을 내 PC 전체에 적용합니다.

만들 파일
~/.claude/CLAUDE.md
내용 예
가정 명시 · 단순함 우선 · 범위 밖 코드 손대지 않기 · 전체 파일 재출력 금지 · .env 읽지 않기
빼도 되나
이미 자기만의 글로벌 규칙을 쓰고 있다면 ‘유지’를 고르세요
ⓑ글로벌 보안해제 비권장

비밀번호·인증서 파일을 Claude가 읽지 못하게 막고, 대화가 압축될 때 알림을 띄웁니다.

만들 파일
~/.claude/settings.json 의 permissions.deny + hooks
막는 것
.env · *.pem · *.key 읽기, 그리고 cat .env 같은 셸 명령을 통한 우회도 함께
한계
파이썬·노드 스크립트가 파일을 직접 여는 건 못 막습니다. 근본 대책은 비밀을 저장소에 두지 않는 것
빼면
Claude가 실수로 비밀번호를 읽고 그게 대화에 남을 수 있습니다. 일부러 빼는 경우가 아니면 그대로 두세요
ⓒ/resume · /wrap · 점검 스킬기본 체크

세션을 시작할 때와 끝낼 때 쓰는 슬래시 명령 두 개 + 구성 점검 명령 두 개. 이 구성의 실질적인 핵심입니다.

만들 파일
skills/resume/SKILL.md · skills/wrap/SKILL.md · skills/dropin-check/ · skills/dropin-update/
/resume
원격이 있으면 먼저 pull로 최신화하고, 커밋 안 된 변경을 찾고(진행 중이던 작업), 지난 기록·계획·최근 결정을 읽어 “지난번엔 X, 다음은 Y?”라고 보고. 설치가 오래됐으면(30일+) 점검을 권해줍니다
/wrap
오늘 한 일을 기록에 추가하고, 새 결정을 남기고, 계획의 체크박스를 갱신하고, 커밋 안 했으면 경고
/dropin-check
내 구성이 문서의 최신 버전으로 적용돼 있는지 점검만(아무것도 바꾸지 않음)
/dropin-update
프로젝트에 넣어둔 문서 사본이 낡았으면 물어보고 최신본으로 교체
종류
resume·wrap은 환경에 따라 셋 중 하나 — 단일 저장소용 기본형 / 팀이 한 저장소를 나눠 쓰는 분할형 / 여러 저장소를 한 폴더에서 다루는 통합형
ⓓ프로젝트 기록 체계기본 체크

기록을 어디에 어떤 형식으로 남길지 정하고, 그 규칙을 프로젝트 CLAUDE.md에 박아둡니다.

만들 파일
docs/PROJECT_PLAN.md(로드맵) · docs/PROGRESS.md(세션 로그) · docs/DECISIONS.md(결정 로그) · .gitattributes
핵심 규칙
기록은 맨 위에 추가만 하고 과거 줄은 고치지 않습니다. 생각이 바뀌면 새 결정을 추가하고 옛것에 “대체됨”을 표시합니다
.gitattributes
merge=union — 두 사람이 동시에 기록을 추가해도 git 충돌 없이 양쪽 다 보존됩니다
ⓔ프로젝트 권한기본 체크

이 프로젝트에서 무엇을 묻지 않고 실행해도 되는지를 정합니다.

만들 파일
.claude/settings.json
allow 예
git status · git diff · npm run · ./gradlew 등 안전하고 자주 쓰는 것
ask 예
git push --force · git reset --hard · rm -rf — 되돌리기 어려운 것
주의
Bash(*)로 전부 허용하는 건 개인 선택 사항이며 팀에는 권장하지 않습니다
ⓕeffort 가이드안내만 · 파일 없음

추론 강도를 언제 올리고 내릴지 설명만 듣습니다. 설정 파일은 만들지 않습니다.

왜 파일을 안 만드나
프로젝트 설정에 effortLevel을 박으면 내가 /effort로 고른 값을 조용히 덮어씁니다. 경고도 안 뜹니다. 그래서 기본값을 쓰고 필요할 때 /effort로 바꾸는 게 낫습니다

함께 확인하는 것 — 프로젝트 유형

코드로 판별한 뒤 “이렇게 이해했다”고 확인만 받습니다.

유형어떤 상황
B (단일)git 저장소 하나. 가장 흔한 경우
A-1 (통합)여러 저장소가 한 상위 폴더 아래 나란히 — 상위 폴더에서 Claude를 켜면 전부 인식됩니다
A-2 (통합)여러 저장소가 흩어져 있음 — --add-dir 옵션이 필요합니다
혼합형한 상위 폴더 아래 git 저장소와 일반 폴더(git 아님)가 섞여 있음 — 폴더마다 맞는 방식을 따로 적용합니다
비-git 폴더git이 아예 없는 폴더 — git 사용을 권하고, 원치 않으면 기록 체계만 깝니다
+MSA 분할위에 더해 여러 명이 한 저장소의 같은 부분을 동시에 고침 → 기록 폴더를 단위별로 쪼갭니다(빌드 모듈 전부가 아니라 실제로 나눠 맡는 단위만). 혼자 쓰면 필요 없습니다

여러 저장소 묶음(A-1·A-2·혼합형)이면 두 가지를 저장소마다 따로 확인합니다 — ① 회사/개인 여부(개인 폴더 안에 회사 저장소가 섞여 있을 수 있어 하나로 묻지 않습니다) ② 하위 저장소까지 함께 설치할지(상위에서 설치해도 하위는 저장소별로 선택). 팀원마다 설치 위치가 달라도(상위 폴더 vs 개별 저장소) 서로 충돌하지 않습니다.

4. 02 모델 분담 — 서브에이전트 로스터

ⓐ~ⓔ + 에이전트 개별 선택 · 개발 프로젝트 전용

비싼 모델과 싼 모델을 일의 난이도에 따라 나눠 쓰는 구성입니다. 어려운 분석·설계는 상위 모델에 맡기고, 잘 정의된 반복 작업은 하위 모델로 돌립니다. 아끼려고 어려운 걸 싼 모델에 밀면 “거의 맞는데 틀린” 결과가 나와 재작업이 더 비싸집니다 — 그래서 분류만큼은 상위 모델이 합니다.

⚠️ 코드가 없는 저장소면 설치하지 않습니다 문서만 있는 저장소에 로스터를 깔면 쓰지도 않는 파일만 늘어납니다. 스캔 결과 빌드·코드가 없으면 Claude가 알리고 중단합니다.

ⓐ~ⓔ 구성 항목

ⓐ난이도 rubric기본 체크

쉬움(易)

통째로가 아니라 하나씩 고릅니다. 지금 하는 일에 맞는 것만 기본 체크됩니다.

체크할 때
계획 단계에서만 특정 모델을 쓰고 싶을 때. 대부분은 필요 없어 기본 해제입니다

5. 03 확장 기능 — 5종 체크리스트

복수 선택 + 스킬은 스코프·호출 방식을 추가로 고름

§1claude-huduser 스코프

입력창 아래에 상태 표시줄을 그려주는 플러그인. 지금 컨텍스트를 얼마나 썼는지, 요금제 한도를 얼마나 소모했는지가 보입니다.

설치 방법
세션에서 /plugin marketplace add jarrodwatts/claude-hud → /plugin install claude-hud → /reload-plugins → /claude-hud:setup
필요한 것
Node.js 18 이상
이럴 때
절약 프로필이면 사실상 필수 — 얼마나 쓰는지 안 보이면 아끼는 건 감에 불과합니다
주의
이미 다른 상태 표시줄을 쓰고 있으면 교체할지 반드시 물어봅니다
§2svg-design디자인 번들

SVG 필터로 만드는 시각 효과(손그림 떨림, 물방울이 붙는 Gooey, 유리 굴절, 네온 글씨)를 제대로 구현하게 하는 규칙집입니다.

만들 파일
skills/svg-design/SKILL.md
막아주는 실수
필터 id 중복으로 화면이 깨지는 문제 · 사파리에서 효과가 잘리는 버그 · 성능을 깎아먹는 설정 · 텍스트를 이미지로 만들어 복사·스크린리더가 안 되는 접근성 문제 · 외부 입력이 들어올 때의 XSS
이럴 때
웹 화면을 직접 만드는 프로젝트. 백엔드나 앱 프로젝트엔 필요 없습니다
§3frontend-design디자인 번들

Anthropic 공식 스킬. “AI가 만든 티가 나는 UI”(뻔한 폰트, 보라색 그라데이션, 과한 애니메이션)를 피하고 주제에 맞는 의도적인 디자인을 하게 합니다.

설치 방법
/plugin marketplace add anthropics/skills 로 묶음 설치, 또는 npx skills add … --skill frontend-design 로 개별 설치
svg-design과 차이
이쪽은 디자인 방향과 전체 UI, svg-design은 SVG 필터 효과 구현. 둘 다 깔아도 충돌하지 않습니다
§4MCP 서버선택

외부 도구를 Claude에 연결합니다. 어떤 서버를 붙일지는 목록으로 따로 물어봅니다.

예
GitHub(PR·이슈·CI 로그 읽기) · Context7(라이브러리 최신 문서 가져오기) · Playwright(브라우저 조작)
스코프
이 repo에서 나만(기본) / 팀 공유 = .mcp.json을 커밋(팀원이 각자 첫 실행 때 승인) / 개인·모든 프로젝트 = claude mcp add --scope user
회사 주의 🔴
MCP 서버는 대화 내용을 외부로 보낼 수 있습니다. 사내 코드를 다루면 조직이 허용한 서버만 연결하세요. 토큰은 환경변수로 넣고 .mcp.json에 직접 적지 않습니다
§5브라우저 검증디자인 번들

만든 화면을 Claude가 직접 열어보고 고치게 합니다. “만들고 → 스스로 확인하고 → 고친다” 루프가 완성됩니다.

경로 3종
Desktop 앱이면 내장 브라우저(설치 불필요) / CLI·IDE에서 Chrome을 쓰면 Claude in Chrome 확장 — 확장 설치만으론 연결되지 않고 claude --chrome이나 /chrome으로 활성화 + /login 인증이 필요하다(WSL 미지원) / 그 외는 참고만
회사 주의 🔴
브라우저를 연결하면 로그인된 세션에도 접근할 수 있습니다. 확장의 사이트 권한을 localhost·스테이징으로 최소화하세요

스킬을 고르면 따라오는 질문 2개

질문선택지

호출 방식 자동 판단 — 관련 작업이 감지되면 Claude가 알아서 불러 씀(기본) / 수동 호출 전용 — 내가 /svg-design이라고 쳐야만 동작(파일에 disable-model-invocation: true 한 줄이 추가됨)

6. 04 검증 자동화 — 3종 체크리스트

“검증했다고 말만 하는 것”을 기계로 막는 장치

“테스트 돌렸습니다”라는 말 대신 실제 실행 출력을 증거로 남기게 하는 규칙이 01에 있습니다. 다만 규칙은 사람도 AI도 잊습니다. 그래서 04는 그걸 2중 게이트로 기계화합니다 — 파일을 고칠 때(훅), 그리고 합치기 전(CI).

§1훅 품질 게이트가장 효과 큼

Claude가 파일을 고칠 때마다 린터·문법 검사가 자동으로 돕니다. 실패하면 그 출력이 Claude에게 전달돼 스스로 고칩니다.

바뀌는 파일
.claude/settings.json 의 hooks.PostToolUse
명령 예
Flutter면 flutter analyze · JS면 node --check · TS면 npm run check-types
넣지 말 것
느린 테스트. 매번 몇 분씩 걸리면 세션이 답답해지고 토큰만 탑니다 — 그건 CI 몫입니다
절약 프로필이어도
이건 빼지 않습니다. 재작업이 줄어드는 게 가장 큰 절약이라서
스코프
팀 공유 = 프로젝트(커밋됨 → 팀원 전원에게 적용되니 회사 저장소는 승인받고) / 개인·전 프로젝트 = 글로벌 / 개인+이 repo만 = .claude/settings.local.json(커밋 안 됨 — 스택별 명령이라 다른 저장소에서 깨질 것 같으면 이쪽)
강도
차단(실패하면 멈추고 바로 고치게 함) / 경고만(알려주고 계속) — 스코프와 함께 물어봅니다
§2호스트 CLI (gh / glab)선택

Claude가 PR을 만들고, 이슈를 읽고, CI 실패 로그를 직접 읽어 고칠 수 있게 하는 명령줄 도구입니다.

어느 것
GitHub → gh / GitLab(사내 포함) → glab / 그 외 호스트 → 설치 안 함
설치
Windows는 winget install GitHub.cli, macOS는 brew install gh → 그다음 gh auth login
인증
본인이 직접 브라우저로 로그인합니다. Claude가 토큰을 만들거나 저장하지 않습니다
§3CI 통합🔴 회사면 조직 승인 필요

PR 단계에서 Claude가 리뷰에 참여합니다. PR에 @claude라고 멘션하면 리뷰하거나 수정합니다.

GitHub
.github/workflows/claude.yml 생성 — 공식 액션 anthropics/claude-code-action@v1
GitLab·기타
GitLab은 공식 CI/CD 통합(베타)의 정본 템플릿을 쓰고, 그 외 호스트는 CI 단계에서 claude -p "…"를 직접 호출하는 방식으로 대체
필요한 것
저장소 Secrets에 ANTHROPIC_API_KEY(Pro/Max 구독은 CLAUDE_CODE_OAUTH_TOKEN도 가능), GitLab은 액세스 토큰 추가. Claude가 대신 넣을 수 없어 직접 등록해야 합니다
회사 주의 🔴
CI에서 코드가 Anthropic API로 전송됩니다. 조직의 외부 AI 사용 정책을 먼저 확인하세요. 승인 없으면 설치하지 않습니다

7. 05 출력 스타일 — 말투와 형식 바꾸기

2종 (복수 선택)

💡 CLAUDE.md와 무엇이 다른가 CLAUDE.md는 “이 프로젝트는 Flutter를 쓰고 테스트는 이 명령으로 돈다” 같은 사실과 규칙을 넣는 곳입니다. 출력 스타일은 Claude의 역할 자체를 바꿉니다 — 시스템 프롬프트를 수정하기 때문에 층이 다릅니다. 같은 내용을 양쪽에 쓰지 마세요.
§1내장 스타일 전환파일 생성 없음

이미 준비된 5종 중에서 고르기만 합니다.

스타일어떤 성격
Default기본. 소프트웨어 작업에 최적화
Proactive더 자율적으로 — 웬만한 건 묻지 않고 추정해서 실행(권한 설정은 그대로 지켜집니다)
Explanatory왜 그렇게 구현했는지 설명하며 진행. 배우는 중이라면 이게 유용합니다
Learning설명에 더해 일부 코드를 직접 짜보게 TODO(human)을 남깁니다
Concise결과를 먼저 제시하고 서론·중계 서술을 생략 — 작업의 철저함은 그대로
바꾸는 법
/config 메뉴의 Output style. 옛 /output-style 명령은 제거됐습니다
⚠️ 함정
지금 세션에는 적용되지 않습니다 — 시스템 프롬프트는 세션 시작 때 한 번만 읽힙니다. 바꾼 뒤 /clear하거나 새 세션을 여세요
§2커스텀 스타일 생성선택

원하는 역할·톤·형식을 직접 써서 마크다운 파일 하나로 만듭니다.

만들 파일
output-styles/<이름>.md
추가 질문
용도(어떤 역할·톤을 원하나) · 스코프(글로벌/프로젝트) · 코딩 지침 유지 여부 · 켤 위치(활성화 키를 어느 설정 파일에 쓸지 — 파일 위치와 별개 축: 기본 피커는 이 repo 개인 설정에만 저장돼, 글로벌에 만들어도 다른 프로젝트에선 안 켜집니다) · 내장 전환과 둘 다 고르면 지금 켤 것 하나도 정합니다
🔴 함정
keep-coding-instructions의 기본값은 false이고, false면 Claude Code의 내장 코딩 지침이 통째로 사라집니다(검증 습관, 최소 변경 원칙 포함). 코딩을 같이 할 거면 반드시 true로 두세요. false는 작가·분석가처럼 아예 다른 역할로 쓸 때만
비용
스타일 본문은 매 세션 시스템 프롬프트에 실리는 고정 비용입니다. 수십 줄 이내로 짧게
적용 안 되는 곳
서브에이전트에는 적용되지 않습니다(각자 자기 프롬프트를 씁니다)

8. 06 루틴 — PC를 꺼도 도는 자동 작업

게이트 통과 후 3종 · research preview 단계

루틴은 Anthropic 클라우드에서 무인으로 실행되는 예약 작업입니다. 내 컴퓨터가 꺼져 있어도 정해진 시각에 저장소를 복제해 작업하고 PR이나 코멘트로 결과를 남깁니다. 예를 들어 야간 PR 리뷰, 주간 문서 점검 같은 것.

🔴 §1 사전 확인 — 여기를 통과 못 하면 설치하지 않습니다 ① 요금제가 Pro 이상이고 Claude Code on the web을 쓸 수 있는가
② 회사 저장소라면 — 조직이 클라우드 실행(코드 반출)을 허용하는가? 루틴은 저장소 전체를 클라우드로 복제하고 프롬프트도 클라우드에 저장됩니다
③ GitHub 저장소인가 (현재 GitHub 전용입니다)
④ claude.ai 계정에 GitHub이 연결돼 있는가 — 안 돼 있으면 프롬프트·스케줄을 다 만들어 놓고 마지막 저장이 거부됩니다(실측)
이 넷은 코드로 확인할 수 없어서 반드시 질문합니다.
§2저장소 준비물선택

클라우드에서 제대로 돌게 만드는 사전 작업.

핵심
루틴은 내 PC에 등록한 개인 MCP를 쓸 수 없습니다. 필요하면 .mcp.json으로 저장소에 커밋해야 합니다
따라오는 것
CLAUDE.md와 .claude/settings.json은 복제본에 포함되므로 그대로 적용됩니다 — 즉 01의 기록 규칙이 클라우드 실행에도 살아 있습니다
§3루틴 생성 — 트리거 3종 중 선택
트리거만드는 법용도 예
스케줄/schedule <자연어> — 최소 간격 1시간, 일회성도 가능주간 문서 점검, 백로그 정리
API웹에서 생성 후 전용 토큰으로 호출모니터링 알림 → 원인 조사 → 임시 PR
GitHub웹 또는 /schedule로 생성 — PR 열림·병합 등 이벤트 + 필터PR 열릴 때 체크리스트 리뷰
같이 정하는 것
대상 저장소 · 프롬프트 · 필요한 커넥터(기본이 전체 포함이라 불필요한 건 빼세요 — 최소 권한)
절약 프로필이면
빈도를 주간부터 시작하도록 제안합니다. 루틴 실행도 요금제 사용량을 씁니다
§4정의 기록 docs/ROUTINES.md기본 권장

루틴 설정은 claude.ai 계정에만 저장되고 저장소에는 남지 않습니다. 계정을 옮기거나 팀원이 같은 걸 만들려면 재현할 근거가 없죠. 그래서 만들 때마다 저장소에 적어둡니다.

💡 루틴이 필요 없는 경우 내 PC의 파일이나 도구가 필요하면 루틴이 아닙니다(클라우드에서 돌기 때문에 내 파일이 없습니다). 그럴 땐 Desktop 앱의 예약 작업이나 세션 안에서 쓰는 /loop를 쓰세요. 루틴은 “컴퓨터가 꺼져 있어도 돌아야 하는 것 + GitHub 이벤트 반응”에만 씁니다.

9. 처음이라면 이렇게 고르세요

상황별 추천 조합

상황모드 · 번들 · 프로필왜
Claude Code를 처음 깐 새 PC 권장 / 번들 없음 / 표준 글로벌 규칙·보안·/resume·/wrap과 상태 표시줄까지. 이것만으로 “어제 뭐 했더라”가 사라집니다
혼자 하는 개인 개발 프로젝트 권장 / 검증 강화 / 표준 기록 체계 + 모델 분담 + 파일 고칠 때마다 도는 자동 검사. 혼자여도 훅 게이트의 효과가 가장 큽니다
웹 화면을 만드는 프로젝트 권장 / 디자인 + 검증 강화 / 표준 디자인 스킬에 브라우저 검증이 붙으면 “만들고 → 직접 열어보고 → 고친다”가 됩니다
Pro 요금제라 한도가 걱정 권장 / 번들 없음 / 절약 상태 표시줄로 사용량을 보면서 effort를 낮춰 시작합니다. 단 검증 게이트는 그대로 둡니다
문서만 있는 저장소 최소 / 번들 없음 / 표준 02(모델 분담)·04(빌드 검증)는 쓸 곳이 없습니다. 기록 체계만으로 충분합니다
회사 저장소 권장 / 회사 + 필요한 번들 / 표준 ‘회사’ 번들은 설치물이 아니라 안전장치입니다 — CI·MCP·루틴처럼 코드가 밖으로 나가는 항목에서 승인 확인을 강제합니다

10. 자주 헷갈리는 것

이미 설치했는데 또 돌려도 되나요?

됩니다. 그게 정상 사용법입니다. 설치가 끝나면 CLAUDE.md 맨 아래에 이런 줄이 남습니다:

<!-- dropin-applied: 2026-08-05 · 모드=권장+디자인 · 프로필=표준 · 언어=ko · 01 v○.○ · 02 v○.○ · 미선택: 05, 06 · 출처=사본 -->

다음에 다시 돌리면 Claude가 이 줄을 먼저 읽고 그 사이에 문서가 무엇이 바뀌었는지 요약해서 보여줍니다. 버전이 같더라도 “기존 항목을 점검할까요? 지난번에 안 고른 것을 추가할까요?”라고 물어보고, 지난번 대기로 남긴 것(예: “gh 인증 대기”)이 있으면 해소됐는지도 함께 확인합니다. 해소됐어도 설치를 원치 않으면 “미선택”으로 바꿔 기록합니다 — 같은 질문이 계속 반복되지 않게요.

체크를 안 하면 나중에 못 넣나요?

언제든 다시 돌려서 추가할 수 있습니다. 문서들은 서로 독립적이라 순서에 크게 얽매이지 않습니다 — 다만 01의 기록 체계가 깔려 있으면 02가 자연스럽습니다.

실수로 뭔가 덮어쓸까 걱정됩니다

설치 전체에 걸친 원칙이 “승인 없이 덮어쓰지 않는다”입니다. 기존 설정이 감지되면 항상 유지/재구성/교체를 묻고, settings.json을 고칠 때도 해당 키만 병합하지 파일을 통째로 갈아치우지 않습니다. 그리고 시크릿(.env·키·인증서)은 읽지도 커밋하지도 않습니다.

설치했는데 /resume이 자동완성에 안 떠요

IDE나 터미널을 재시작해보세요. 그래도 안 되면 폴더·파일 이름(skills/resume/SKILL.md)과 파일 맨 위의 name: 줄을 확인하면 대부분 해결됩니다.

/resume을 치면 같은 이름이 여러 개 떠요 — 잘못 깔린 건가요?

대부분 정상입니다. 팀 공유용으로 repo(.claude/skills/)에도 넣고 실제 실행용으로 내 PC(~/.claude/skills/)에도 넣는 구성이라, 한 PC에 같은 이름의 사본이 둘 있고 자동완성은 그걸 따로따로 보여줍니다. 어느 것을 골라도 내 PC 쪽이 실행됩니다(공식 우선순위). 확인할 것은 개수가 아니라 두 사본의 내용이 같은가입니다 — 다르면 Claude에게 “글로벌 스킬을 repo 사본으로 맞춰줘”라고 하세요. 예외: 옛 방식 폴더 ~/.claude/commands/resume.md가 남아 있어서 2개가 뜨는 경우는 그 파일을 지우면 됩니다.

“문서 버전”이 계속 올라가는데 매번 따라가야 하나요?

아닙니다. 대부분의 버전 업은 공식 문서를 다시 확인하고 “여전히 유효함”을 기록한 것입니다. 실제로 설치물이 달라지는 변경은 버전 표에 굵게 표시되니, 재적용할 때 Claude가 보여주는 요약만 보고 판단하면 됩니다.
