    Chapter 0 · about 2 minutes

    The choices the installer offers,
    learned by clicking them

    Drop this repository’s documents into a project, say “read this and apply it”, and Claude asks you to make a few choices. This course recreates those questions as the real screens and shows you, right there, what gets created and what changes for each option.

    • The chapters are built to be read in order, but you can jump around with the contents on the left.
    • When a simulator appears, click through it. It sticks far faster than reading alone.
    • Your progress is stored in this browser only. Nothing is sent to a server.
    📖
    The dictionary to look things up, this course to learn the shape The same material is organized item by item in the install options dictionary. Mid-install, when you think “what is this?”, the dictionary is faster; for the whole picture the first time, this course is better.

    Chapter 2 · how an install flows

    Across five steps, questions come at only two of them

    Claude investigates before it asks. Anything the files can answer — what is already installed, whether this is git, which language the code is in — is never asked; only what the code cannot tell it. Click each step for detail.

      📌
      The detailed questions appear only in “custom” mode In minimal, recommended and full, the per-document items are settled automatically at that mode’s defaults. The safety questions (“overwrite what is already here?”, “have you checked company policy?”) are never skipped, in any mode.

      Chapter 7 · items inside a document ②

      For development projects — 02 split · 03 add-ons · 04 verification

      Three documents that only mean something where there is code. Expand them one at a time.

      02Model split — expensive and cheap models, divided development only

      Installs a subagent roster that sends hard analysis and design to the stronger model and well-defined repetitive work to the cheaper one. Push hard work onto a cheap model to save money and you get results that are almost right but wrong, and the rework costs more — which is why the triage itself always uses the stronger model.

      AgentWhat it doesModel
      surveyorSweeps the structure broadly and mechanically into a list (no judgments)sonnet
      triageScores that sweep for difficulty — the seat that matters mostopus
      analystAnalyzes the hard parts and writes the implementation specby difficulty
      spec-writerPins down requirements for a new feature — step one of building something newopus
      implementerBuilds to the spec (nothing outside scope)sonnet
      parity-testerRuns the tests and reports pass/diff onlyhaiku

      Agents are chosen one at a time, not as a block. Changing existing code → the five without spec-writer; building something new → drop surveyor and triage and start from spec-writer. No reviewer is created — the built-in /code-review is already there.

      There is one more optional item (unchecked by default) — a /plan-<model> command that runs a different model only while planning. When the plan is done it returns to your normal model by itself.

      ⚠️
      Not installed in a repository with no code A roster in a documentation-only place just adds files nobody uses. Claude detects that and tells you.
      03Add-ons — status line, design skills, MCP, browser five optional
      • claude-hud — a status line under the input box showing context and plan usage. Practically required on the thrift profile.
      • svg-design — a rulebook for implementing SVG effects (hand-drawn, Gooey, glass, neon) correctly. For projects that build web screens.
      • frontend-design — an official Anthropic skill that steers away from UI that looks AI-generated.
      • MCP servers — connect external tools (GitHub, doc search, browser control). Which servers to attach is asked separately.
      • Browser verification — lets Claude open the screens it built, check them and fix them.

      Choosing a skill brings two more questions — scope (your whole machine vs. this project only) and invocation (Claude decides vs. only when you type /command).

      🔴
      At work MCP can send your conversation outside, and a connected browser can reach your logged-in sessions. Connect only servers your organization allows, and narrow the extension’s site permissions to localhost.
      04Verification — machine checks instead of “it’s done” the hook gate is the core
      • Hook quality gate — a linter or syntax check runs every time Claude edits a file, and the failure output goes back to Claude, which fixes it itself. Never dropped, even on the thrift profile — less rework is the biggest saving there is.
      • Host CLI (gh/glab) — lets Claude open PRs and read CI failure logs directly. You sign in yourself.
      • CI integration — mention @claude on a PR and it reviews or fixes. 🔴 org approval required at work — CI sends your code to the Anthropic API.

      Slow tests do not go in the hook — minutes on every edit makes the session sluggish. That is CI’s job.

      Chapter 8 · items inside a document ③

      05 output styles · 06 routines

      05Output styles — changing Claude’s tone and role optional

      Pick one of the five built-ins (Default, Proactive, Explanatory, Learning, Concise), or write the role and tone you want into a single markdown file. While you are learning, Explanatory — which explains why it did things that way as it goes — is the useful one.

      🔴
      The custom-style trap — keep-coding-instructions It defaults to false, and false makes Claude Code’s entire built-in coding guidance disappear (verification habits and the minimal-change principle included). If you will also be coding, set it to true.

      One more thing — switching a style does not affect the current session. The system prompt is read once, at session start, so open a new session after switching.

      06Routines — cloud jobs that run with your PC off three gate questions

      Scheduled jobs that run unattended in the Anthropic cloud — nightly PR review, weekly doc checks, that sort of thing. Before installing, three things are always asked, because the code cannot answer them.

      • ① Is your plan Pro or above (and is GitHub connected to your claude.ai account)?
      • ② For a company repository — does your organization permit cloud execution (code leaving the building)?
      • ③ Is it a GitHub repository? (GitHub only, for now)
      💡
      If it needs files on your machine, it is not a routine Routines run in the cloud, where your files do not exist. Use them only for “must run with the computer off”.

      Chapter 10 · wrapping up

      🎓

      Course complete!

      Three things to remember

      • Unsure? Recommended mode — Claude shows you why it combined things that way and asks you to confirm.
      • Whatever you choose, nothing is overwritten without approval, and secrets are neither read nor committed.
      • Skipping a checkbox is fine — run it again later and add it. The install record is there, so it picks up from where it was.
