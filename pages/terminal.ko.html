왜 이 구성인가

Claude Code는 오래 도는 일을 맡기는 도구인데, 기본 터미널에서는 세션이 창에 묶여 있다. 창을 닫거나 SSH가 끊기면 대화 옆에서 돌던 서버·테스트·git 화면도 함께 사라진다. 그리고 자리를 떠나면 휴대폰이나 다른 PC에서 이어 받을 길이 없다.

세션을 창에서 분리

터미널 멀티플렉서(psmux)나 Claude Code의 agent view로 창을 닫아도 일이 계속된다.

여러 화면을 한 번에

Claude, 서버, git을 나란히 놓고, Claude가 옆 칸의 오류를 직접 읽게 한다.

원격에서 이어받기

Remote Control로 휴대폰·브라우저에서 같은 세션을 이어 간다.

macOS와 같은 손맛

y z ll lg 같은 별칭을 Windows에서도 같게 쓴다.

추천 구성: 지금 구성은 두고 세 층을 얹는다

터미널과 셸을 바꿀 이유는 없다. Windows Terminal은 꾸준히 갱신되고 PC에 기본으로 깔려 있다. 부족한 것은 세션이 창에 묶인다는 점과 원격에서 이어받을 수단이고, 아래 층이 그 둘을 채운다.

사용 요령

설치를 마친 뒤 골라 쓰는 요령이다. 설정 파일을 고쳐야 하는 요령은 설치 후로 표시했고, 그 설정 조각은 설치 문서가 나오면 거기에 둔다.

psmux를 더 잘 쓰기
  • yazi를 옆 칸에 바로 열기 설치 후 — 키 하나를 추가하면 Ctrl+b → Tab이 지금 폴더의 yazi를 오른쪽 칸에 연다. q로 닫으면 칸도 닫힌다.
  • 프로젝트 화면을 스크립트 한 번에 설치 후 — Claude, 서버, git 칸을 매번 손으로 나누지 않고 스크립트가 만든다. 세션이 이미 있으면 붙기만 한다.
  • 옆 칸의 오류를 Claude에게 넘기기 — 서버 칸에 Ctrl+b → T로 이름을 붙이고 “서버 칸 마지막 50줄 읽고 오류 원인 정리해 줘”라고 한다. Claude가 psmux capture-pane -p -t main:1.2로 읽고, psmux send-keys로 다른 칸에 명령도 보낼 수 있다. main:1.2는 세션:창.칸이다.
  • 프로젝트마다 세션 하나 설치 후 — tm api, tm web처럼 이름을 주면 세션과 칸 구성이 따로 남는다. 옮길 때는 Ctrl+b → s.
  • 칸이 많아 헷갈릴 때 — Ctrl+b → q로 번호를 띄우고 숫자를 누르거나, Ctrl+b → w로 전체를 나무로 본다. 좁은 칸은 Ctrl+b → z로 잠깐 크게 본다.
  • 여러 AI로 교차 검증 정책 확인 — 다른 칸에 Codex CLI·Gemini CLI 같은 에이전트를 띄워 같은 질문을 보내고 결과를 읽어 와 종합하게 한다. 각 CLI는 따로 설치·로그인해야 한다. 회사나 기관이 관리하는 PC에서는 외부 AI 도구가 허용되는지 먼저 확인한다 — 코드가 각 회사 서버로 나간다.
  • tmux 명령도 그대로 — psmux를 설치하면 tmux·pmux 이름도 함께 생겨, macOS·Linux에서 쓰던 tmux 명령과 스크립트를 그대로 칠 수 있다.
셸과 도구
  • 오류 출력을 Claude에게 설치 후 — 실패한 명령 바로 뒤에 Ctrl+Shift+↑ → Ctrl+C → Claude 입력 줄에 Ctrl+V. 드래그로 고를 필요가 없다(셸이 명령 경계를 표시해 줘야 한다). psmux 안에서는 미확인
  • 파일 경로를 Claude에게 — yazi에서 파일을 고르고 c c로 경로를 복사해 Claude 입력 줄에 @와 함께 붙여 넣는다.
  • Claude가 고친 것 검토 — 다른 칸에 lg를 열어 두면 바뀐 파일이 바로 보인다. Enter로 들어가 줄 단위로 골라 커밋하고, 실수하면 z로 직전 git 작업을 되돌린다(이미 푸시한 커밋은 원격까지 되돌리지 못한다).
  • 지난 명령 다시 치기 — 처음 몇 글자를 치고 F8, 또는 Ctrl+R 뒤 낱말 일부.
  • yazi를 닫으면 그 폴더로 이동 설치 후 — 셸 함수 하나로 q로 나왔을 때 마지막에 보던 폴더로 옮겨 간다. 옮기지 않고 나갈 때는 Q.
  • fzf·ripgrep — 따로 설치하면 검색 세 가지가 살아난다: zi(후보를 골라 폴더 이동), yazi의 z(파일 점프), yazi의 S(파일 내용 검색).
  • 자주 가는 폴더를 미리 알려 주기 — 설치 직후 z는 아무것도 모른다. zoxide add D:\work\my-app처럼 넣어 두면 바로 z my-app이 된다. 잘못 기억한 폴더는 zoxide remove 경로.
  • 폴더 구조를 나무로 — eza -T -L 2는 두 단계까지 나무로, ll -T -L 2는 git 상태도 함께 보여 준다.

psmux 마우스 — tmux와 다른 점

tmux는 마우스가 기본으로 꺼져 있지만 psmux는 켜져 있다. 칸 클릭으로 이동, 경계선 끌기로 크기 조절, 상태 줄의 창 이름 클릭으로 전환, 휠로 스크롤, 끌어서 선택(놓으면 클립보드로 복사), 오른쪽 클릭으로 붙여넣기가 된다. Shift를 누른 채 끌면 터미널 자체의 선택을 쓴다. 끄려면 set -g mouse off.

하지 말 것: 강의·블로그를 보고 바꾸기 쉬운 설정
설정Windows에서 생기는 문제
prefix를 Ctrl+Space로 변경PowerShell의 완성 후보 목록(MenuComplete)이 이 키를 쓴다. 바꾸면 그 기능을 잃는다. prefix는 Ctrl+b를 유지한다.
prefix 없이 Alt+h j k l로 칸 이동Alt+h는 PowerShell 매개변수 도움말이다. Claude Code 안에서의 충돌은 확인하지 못했다. prefix 키를 쓴다.

Ghostty로 터미널 교체공식 Windows 버전이 없다. Windows Terminal을 유지한다.

psmux 없이 쓰기

psmux를 쓸 수 없는 PC에서 Windows Terminal의 분할 패널로 Claude 세션 여러 개를 나란히 돌리는 방법이다. 이 방식은 창을 닫으면 세션도 끝나므로, 세션 유지는 agent view(claude --bg)가 맡는다.

2×2 만들기

  1. 새 탭에서 프로젝트 폴더로 이동해 claude를 실행한다.
  2. Alt+Shift+＋ → 오른쪽 패널에서 claude --worktree my-app-2.
  3. Alt+Shift+− → 오른쪽 아래에서 claude --worktree my-app-3.
  4. Alt+←로 왼쪽에 가서 Alt+Shift+− → 왼쪽 아래에서 claude --worktree my-app-4.

왜 워크트리인가 — 같은 폴더에서 세션 둘이 돌면 작업 트리와 git 인덱스를 공유해 서로의 미커밋 변경이 섞인다. claude --worktree 이름은 .claude/worktrees/이름/에 worktree-이름 브랜치로 따로 checkout을 만든다. 단디를 쓴다면 이름 규칙이 있으니 아래 「단디와 함께」를 본다.

단축키

이 구성에서 쓰는 키를 한 곳에 모았다. ★는 핵심 키이고, 설치 후는 설정 파일이나 별칭을 넣은 뒤에만 되는 키다.

Ctrl+b → | 는 Ctrl과 b를 함께 눌렀다가 둘 다 떼고, 그다음 |를 누른다는 뜻이다. 방향·크기 조절 키는 prefix를 한 번 누른 뒤 0.5초 안에 이어 누르면 prefix 없이 반복된다.

단디와 함께 쓸 때

  • 세션 유지: 단디의 운영 문서(01 §D)는 멀티플렉서보다 agent view를 먼저 권한다. psmux는 그 위에 얹는 선택 사항이다.
  • 워크트리 이름: 단디는 .claude/worktrees/NNN-요약처럼 번호를 붙이고 /resume NNN으로 찾는다. 위 2×2 예시의 my-app-2나 agent view가 붙이는 자동 이름은 번호가 없어 그 방법으로 찾지 못한다.
  • 동시 에이전트 수: 단디의 agent-guard가 PC 사양에 맞춰 동시에 돌 서브에이전트 수를 제한한다. agent teams 팀원을 칸으로 띄웠을 때 팀원이 그 수에 포함되는지는 확인하지 못했다.
  • Windows 점검: Windows Terminal 기본 프로필, PATH, Git 같은 PC 상태는 단디의 /win-setup이 진단한다. 이 페이지는 그 내용을 되풀이하지 않는다 — 스킬 카탈로그 참고.
  • lazygit: 설치와 diff 도구 설정은 설치 옵션 사전의 §16 diff 검수 도구가 다룬다. 여기서는 쓰는 요령만 둔다.

설치

설치는 별도 문서 terminal-setup.md로 진행한다Claude Code가 읽고 이 PC를 읽기 전용으로 진단한 뒤, 판정표를 보여 주고 항목마다 승인을 받아 설치·설정한다. 막혔을 때 표와 되돌리기도 그 문서에 있다. 단디의 통합 설치(00 문서)에는 들어가지 않으니, 필요할 때 Claude Code에 “이 문서를 읽고 터미널 구성을 진행해 줘”라고 요청한다. 실습 시나리오는 아직 없다.
