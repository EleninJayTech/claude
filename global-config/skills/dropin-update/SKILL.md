# /dropin-update — 드롭인 문서 최신화 (승인 후 교체)

**역할 경계**: 이 스킬은 **문서 파일만** 갱신한다 — 구성 재적용(00 "학습해서 적용해줘")·적용 상태 점검(`/dropin-check`)은 하지 않는다.
**저장소 원본 안에서는 실행하지 않는다** — 현재 repo remote가 `EleninJayTech/claude`면 "여기는 원본 — `git pull` 사용"이라고 안내하고 중단.

## 0) 설치 유형 판별 — 셋 중 하나, 어떤 유형이든 계속 진행한다
- **통합 워크스페이스**(상위 폴더 아래 독립 repo 여러 개)면 대상 repo별로 판별·최신화한다(루트 레이어 기록은 루트 CLAUDE.md — /dropin-check와 같은 패턴).
- **글로벌 전용 설치**(프로젝트에 기록이 없거나 `~/.claude/CLAUDE.md`에만 `dropin-applied`가 있는 경우)면 **글로벌 기록의 `출처=`로 판별**한다 — 현재 PWD에 `NN_*.md`가 없다고 곧바로 raw로 넘기지 말 것(문서를 다른 폴더의 사본에서 읽어 글로벌만 적용한 PC가 흔하고, 그러면 정작 낡은 사본이 원래 위치에 그대로 남아 다음 재적용에 다시 쓰인다). `출처=사본`인데 경로가 불명확하면 사용자에게 그 사본 위치를 묻는다.
- 대상 `CLAUDE.md`의 `dropin-applied` 줄에 `출처=` 필드(00 v1.10+)가 있으면 그대로 따른다: `출처=사본` / `출처=클론 <경로>` / `출처=raw`. 단 **기록=raw인데 프로젝트에 문서 사본(`NN_*.md` 버전 헤더)이 보이면 사본으로 재판별**(과거 raw→사본 전환 후 기록 미갱신 사례).
- 출처 기록이 없으면(구버전 기록·기록 자체 없음) 순서대로 판별:
  ① 프로젝트 루트·`docs/`에 `NN_*.md`(최상단 `> **문서 버전: vX.Y**` 헤더) 있음 → **사본**
  ② 없으면 사용자에게 설치 때 참조한 **로컬 클론**이 있는지 질문(후보: remote가 `EleninJayTech/claude`인 폴더 — 경로는 PC마다 다르다) → 있으면 **클론**
  ③ 둘 다 없으면 **raw** — 사본·클론을 지웠어도 이 분기로 계속 진행한다(중단 아님).

## 1) 유형별 최신화
> **공통 종료 규칙**: 어느 유형이든 기준(원격·클론)을 확보하지 못하면 **"최신화 불가"로 보고하고 종료**한다 — 추측 비교 금지, 재시도 루프 금지(`/dropin-check` §1과 같은 규칙).
> 기준은 확보했으나 **적용(pull·교체)에 실패한 경우도 마찬가지로 종료**한다 — 확보한 기준(`origin/main`)으로 비교 보고까지 마치고, `/dropin-check`를 다시 부르라고 되돌려 보내지 않는다.
- **사본**: ⓐ 저장소 최신 확보 — **로컬 클론 우선**(/dropin-check §1과 같은 사다리: 출처 기록 경로 → remote가 `EleninJayTech/claude`인 폴더 탐색 → 질문). **클론을 기준으로 쓸 땐 먼저 `git fetch`로 뒤처짐을 확인하고, behind > 0이면 승인 후 `git pull --ff-only`**(더티·ff 불가면 pull 대신 `git show origin/main:<파일>`을 기준으로 비교) — fetch 없이 워킹트리를 기준 삼으면 낡은 사본과 낡은 기준을 비교해 "전부 최신"이 나온다. 클론이 없으면 GitHub API(`https://api.github.com/repos/EleninJayTech/claude/contents/`)에서 같은 파일명의 download_url을 얻어 **헤더만** 조회(전체 다운로드는 승인 후. 오프라인+클론 없음이면 "최신화 불가" 보고 종료). ⓑ 표로 보고: `문서 | 로컬 vX.Y → 최신 vX.Z | 주요 변경`(최신 문서 버전 표에서 로컬 버전 이후 행 요약). 전부 최신이면 "최신 — 조치 불요"로 종료. ⓒ **사용자 확인(무단 교체 금지)** — 전체/개별을 묻고, 로컬 사본에 원본에 없는 수정 흔적이 보이면 경고 후 개별 확인(덮어쓰면 소실). ⓓ 승인된 문서만 raw에서 받아 같은 경로에 덮어쓰고, 각 파일 버전 헤더를 다시 읽어 **증거로 보고**.
- **클론**: 그 클론에서 `git fetch` 후 뒤처짐(behind 커밋 수)을 보고 → 워킹트리 clean이고 ff 가능하면 승인 받아 `git pull --ff-only`. **더티·ff 불가면** 보고만 하고(병합은 사용자 결정) **`git show origin/main:<파일>`을 기준으로 버전 비교까지 마친 뒤 종료한다** — "pull 못 함"만 알리고 끝내면 `/dropin-check`가 다시 이 스킬을 권고해 같은 권고가 무한 반복된다(재권고 금지). 갱신 후 문서 버전 표 헤더를 읽어 증거로 보고. **기록엔 클론인데 경로가 사라졌으면** raw 분기로 계속 진행 + "클론 삭제됨 — 재적용은 GitHub raw 최신본 사용(원하면 재클론)" 고지.
- **raw(또는 사본·클론 삭제됨)**: 갱신할 로컬 파일이 없다 — 대신 `dropin-applied`의 문서별 적용 버전을 저장소 최신과 비교해 표로 보고(뒤처진 문서와 주요 변경). **적용 기록 자체가 없으면**(§0 ③으로 온 경우가 흔하다) 비교 대상이 0건이라 표에 쓸 것이 없다 — "적용 기록 없음 — 비교 생략. `/dropin-check`로 상태 확인 또는 00 재적용으로 기록 수립"을 알리고 **종료**한다(빈 표를 내면 사용자가 "최신화됐다"로 읽는다). 이어서 선택지를 제시: ⓐ 최신 사본을 프로젝트에 내려받아 두기 — 이후 '사본' 유형으로 관리하며 **`dropin-applied`의 `출처=`를 `사본`으로 갱신**(기록이 raw로 남으면 다음 판별이 현실과 어긋난다) ⓑ 그대로 두기 — 재적용 시 항상 raw 최신본이 사용되므로 파일이 없어도 문제없다.

## 2) 마지막 안내 (유형 공통)
"문서 갱신됨(raw 유형은 비교 보고) — 구성에 반영하려면 00 문서로 재적용('학습해서 적용해줘', 재적용 분기가 버전 diff 안내). 적용 상태 점검은 `/dropin-check`."
