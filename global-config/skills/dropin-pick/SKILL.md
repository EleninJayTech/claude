# /dropin-pick — 드롭인 분류 설치 (고른 설치 형태만)

**역할 경계**: 전체 구성 재적용은 `/dropin-apply`, 작업 신호로 추천받아 까는 것은 `/dropin-apply 추천`, **사용자가 설치 형태를 직접 골라 그것만 까는 것은 이 스킬**이다. 점검(읽기 전용)은 `/dropin-check`.

🔴 **절차와 분류 표의 정본은 `00_통합-설치.md` §C-5다** — 이 파일에 분류 표나 설치 단계를 적지 않는다(사본은 갈린다). 00을 고치면 이 스킬도 따라온다.

## 0) 00 문서 확보
- `/dropin-apply` §0과 같다 — 00 §A STEP 1의 확보 사다리를 **00 자신에게 적용**한다(사다리를 여기 다시 적지 않는다).
- 어느 rung에도 닿지 못했을 때의 최후 경로: `https://raw.githubusercontent.com/EleninJayTech/claude/main/00_통합-설치.md` (한글 파일명은 URL 인코딩 — **바이트 그대로** `curl`/`Invoke-WebRequest`로 **프로젝트 밖 임시 폴더에** 받는다. WebFetch는 요약 도구라 쓰지 않는다).
- **확보한 00에 §C-5가 없으면**(옛 사본) 00 STEP 3의 사본 최신화 권장(`/dropin-update` 선행)을 먼저 거친다. 그래도 없으면 중단하고 "이 00에는 분류 설치가 없다 — `/dropin-apply`로 전체 경로를 쓰라"고 알린다.

## 1) 수행 — 00 §C-5에 위임
- 인수를 §C-5 표의 **부르는 이름**과 대조해 분류를 정한다. 맞는 것이 없거나 인수가 없으면 §C-5대로 묻는다.
- **확보한 00의 §A STEP 1~5와 §C-5를 Read로 읽고**, §C-5가 바꾸는 자리만 바꿔 그대로 수행한다.

## 2) 하지 않는 것
- **분류를 자동 확정으로 읽지 않는다** — 고른 분류 안 항목도 그 문서의 질문으로 제시한다(기본 해제는 해제 상태로).
- **안전 질문·게이트·불변 ①~④를 생략하지 않는다** — 분류 설치가 갈음하는 것은 모드·번들 질문뿐이다.
- **고르지 않은 분류의 문서를 설치하지 않는다.**

## 3) 끝나고
- 검증·보고·적용 기록은 **00 STEP 5가 맡는다**(형식은 §C-5 5항).
- 나머지 분류가 필요해지면 다시 `/dropin-pick <분류>` 또는 `/dropin-apply`.
