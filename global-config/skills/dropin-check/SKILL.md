# /dropin-check — 드롭인 구성 최신성 점검 (읽기 전용)

**변경 금지**: 이 스킬은 점검·보고만 한다. 문서 사본 갱신은 `/dropin-update`, 재적용은 00_통합-설치.md("학습해서 적용해줘"),
글로벌 복원은 `global-config/` 복사(DEC-20260721-bsjeong87-01).

## 1) 기준 확보 — 문서 저장소의 현재 버전
- 대상 `CLAUDE.md`의 `dropin-applied`에 `출처=클론 <경로>`(00 v1.10+)가 있으면 그 경로를 클론 후보 최우선으로 쓴다.
- 로컬 클론 탐색: remote가 `EleninJayTech/claude`인 폴더를 찾는다(흔한 위치 예: `D:\claude`·`D:\workspace\claude` — 경로는 PC마다 다르니 고정값으로 믿지 말 것). 없으면 사용자에게 경로를 묻고,
  그것도 없으면 GitHub API(`https://api.github.com/repos/EleninJayTech/claude/contents/`)에서 파일 목록·download_url을 얻어 원격 조회(한글 파일명 인코딩 회피).
- 로컬 클론이면 점검 전 `git fetch`만 한다 — 이 스킬은 읽기 전용이라 `pull`은 하지 않는다(사용자가 그 클론에서 편집 중일 수 있다).
  **fetch 뒤 비교 기준은 워킹트리가 아니라 `origin/main`이다**(`git show origin/main:<파일>`) — fetch만 하고 워킹트리를 읽으면 뒤처진 파일로 비교해 "최신" 오보가 그대로 난다.
  behind 커밋 수를 병기하고, **behind > 0이면 §4의 "최신 — 조치 불요" 판정을 쓰지 않는다**(클론 워킹트리가 낡았다는 사실을 먼저 보고 + "`/dropin-update`로 클론 최신화" 권고).
- **오프라인이고 로컬 클론도 없으면**(원격 조회 실패) "점검 불가"로 보고하고 종료한다 — 추측 비교 금지.
- 각 드롭인 문서(`NN_*.md` 전부, 현재 00~06)의 **최상단 헤더+버전 표만** 읽어 `문서 버전: vX.Y`와 §4 인용 재료(해당 버전 행)를 추출한다(전체 Read 금지). 읽는 범위는 줄 수 상수가 아니라 **버전 표가 끝나는 줄까지**(`※ 갱신 시:` 직전) — 표는 개정마다 자라므로 고정 상수를 쓰면 최신 행부터 잘려 "차이 있음, 내용 미상"이 된다.

## 2) 적용 기록 점검 — 대상 프로젝트
- 대상(현재 PWD 프로젝트)의 `CLAUDE.md`(루트 또는 `.claude/`) 맨 아래 `<!-- dropin-applied` 로 시작하는 줄 파싱: 적용일·모드·프로필·문서별 버전·미선택·출처(있으면). **`dropin-applied` 뒤에 괄호 한정자가 붙을 수 있다**(예: `dropin-applied(글로벌 · 머신=YOGASLIM7):` — 00 §A STEP 5) — `dropin-applied:` 리터럴로만 찾으면 그런 줄을 "기록 없음"으로 오판한다.
- **통합 워크스페이스**(상위 폴더 아래 독립 repo 여러 개)면 루트와 하위 repo **각각**의 CLAUDE.md 기록을 점검한다(resume/wrap과 같은 패턴 — 루트 레이어분은 루트, repo 적용분은 각 repo).
- **프로젝트 기록에 글로벌 항목(01 §D)이 포함됐거나 글로벌만 적용한 PC면 `~/.claude/CLAUDE.md`의 기록도 함께 파싱**해 스코프별로 나란히 보고한다. 00 v1.12+는 프로젝트 설치에 글로벌분이 있으면 **양쪽에 병기**하므로, 글로벌 줄을 "글로벌 전용 설치"일 때만 읽으면 가장 흔한 경우를 통째로 놓친다(프로젝트 기록만 최신이고 글로벌 기록이 6개 버전 낡아도 "최신 — 조치 불요"가 나온다. 2026-08-12 실사례).
- 기록이 없으면: "적용 기록 없음(미적용이거나 2026-08-04(기록 도입) 이전 적용)"으로 보고하고 문서 비교는 생략.
- 흔적으로 추정할 때(기록 없음·02 적용 범위 확인): `.claude/agents/` 로스터만 보지 말고 rubric·핸드오프 산출물(`model-routing.local.md`·`.claude/specs/` 등)과 `.gitignore`·`.git/info/exclude`도 조회 — 02 산출물은 전부 로컬 전용일 수 있어 파일 부재≠미적용(2026-08-10 오판 실사례). **`~/.claude/agents/`(개인 스코프)도 함께 본다** — 02 v1.17이 개인 배치를 허용하므로 프로젝트 경로만 보면 "미적용"으로 오판해 중복 로스터를 만들고, 개인 쪽이 이기므로 새로 만든 게 실행조차 안 된다.

## 3) 글로벌 구성 대조 — 화이트리스트 5종
- `~/.claude`의 `CLAUDE.md`·`settings.json`·`skills/`·`commands/`·`output-styles/`를 저장소 `global-config/`와 파일 단위 대조(없음/내용 다름).
- **로컬 클론이 없으면 이 절은 "대조 불가(저장소 클론 필요)"로 보고하고 건너뛴다** — §1의 GitHub API 폴백은 드롭인 문서의 헤더·버전 표만을 위한 것이라 `global-config/` 전문 대조를 대신하지 못한다. 추측 비교 금지.
- `settings.json`은 **구성 성격 키(`permissions.deny`·`hooks`·`attribution`·`autoMemoryEnabled`)의 차이만** 보고한다 —
  그 밖은 전부 머신 종속이라 달라도 정상(model·theme·outputStyle·enabledPlugins·statusLine·effortLevel·autoUpdatesChannel·
  마켓플레이스 소스 형식 등, DEC-20260721-bsjeong87-02). 괄호는 예시이므로 **제외 목록을 늘리지 말고 포함 기준으로 판정**한다.
- **줄바꿈을 정규화한 뒤 비교** — `core.autocrlf=input` 저장소는 커밋본이 LF, Windows 정본은 CRLF라 내용이 같아도 파일 해시가 갈린다(pull 직후 오검출). 줄바꿈만 다르면 차이로 치지 않는다.
- 어느 쪽이 최신인지 단정하지 말 것 — 백업 규칙상 원본(`~/.claude`) 수정이 백업에 자동 반영되지 않으므로, 차이의 방향(로컬이 구버전 / 백업이 구버전)을 파일 내용으로 판단해 명시.
- **중복 등록 감지**: `commands/<이름>.md`와 `skills/<이름>/`이 같은 이름이면 "구형 잔재 — `/` 자동완성 2개·구형 내용 실행 위험, commands 쪽 삭제 권고"로 보고(정본은 skills, DEC-20260810-bsjeong87-04). 프로젝트 `.claude/commands/`↔`.claude/skills/`도 동일 점검.

## 4) 보고 (표 + 증거, 변경 없음)
- 문서별: `적용 vX.Y → 현재 vX.Z` + 차이 한 줄(현재 문서 버전 표의 해당 행 인용). 미선택 문서·부분 적용 괄호 메모·**"사용자 조치 대기"·`게이트 차단(사유)`** 항목도 표시한다(차단 기록은 "미선택"과 달리 **재확인 대상** — 조직 승인·요금제 같은 조건이 바뀌었으면 00 재적용으로 다시 묻게 안내). **기록 버전이 현재 문서 버전보다 높으면** 소스가 낡은 것이므로 그 사실을 먼저 보고한다(전진 방향만 가정하지 않는다).
- 글로벌: 항목별 일치/차이 목록(예: `skills/resume` 내용 다름 — 백업엔 pull-first 있음, 로컬은 구버전).
- 마지막 줄 권고: 문서 차이 → "로컬 문서 사본이 구버전이면 `/dropin-update`로 먼저 갱신 → 00 문서 재적용(재적용 분기가 버전 diff를 안내)" / 글로벌 차이 → **§3에서 판단한 방향대로 2분기**: 로컬(`~/.claude`)이 구버전이면 "`global-config/`에서 해당 파일 복사", 백업이 구버전이면 "원본을 `global-config/`로 복사해 백업 갱신·커밋"(최신 로컬을 구백업으로 덮지 않는다). **복사를 담당하는 전용 스킬은 없다** — 이 스킬은 읽기 전용이고 `/dropin-update`는 문서 파일만 다루므로, **실행 가능한 복사 명령을 그대로 제시**하고 실행은 사용자에게 맡긴다(`Copy-Item <원본> <대상> -Force` 형태로 방향까지 확정해 적어 준다. 실행 후 `/wrap`의 미러 대조가 해시로 확인해 준다). **이 스킬이 직접 복사·삭제하지 않는다** — 읽기 전용 계약(맨 위 "변경 금지")이 우선이고, §3의 방향 판정이 틀렸을 때 최신 로컬을 구백업으로 덮는 사고를 스스로 저지르지 않기 위해서다. `commands`↔`skills` 이름 중복도 같은 방식(삭제 명령 제시까지) / 적용 기록 없음 → "00 재적용으로 기록 수립 권장"(흔적 감지 한계 해소) / 전부 일치 → "최신 — 조치 불요".
