# /dropin-check — 드롭인 구성 최신성 점검 (읽기 전용)

**변경 금지**: 이 스킬은 점검·보고만 한다. 문서 사본 갱신은 `/dropin-update`, 재적용은 00_통합-설치.md("학습해서 적용해줘"),
글로벌 복원은 **01 §D-2·§D-3 블록으로 재구성**한다(그 블록이 유일한 정본 — 어느 저장소를 가졌든 같은 결과가 나와야 한다).
유지보수자가 **개발 저장소(`claude-dev`) 클론**을 가진 경우에만 그쪽 `global-config/` 사설 백업을 복원에 쓸 수 있다(DEC-20260721-bsjeong87-01).

## 1) 기준 확보 — 문서 저장소의 현재 버전
- 대상 `CLAUDE.md`의 `dropin-applied`에 `출처=클론 <경로>`가 있으면(그 필드가 있는 기록이면) 그 경로를 클론 후보 최우선으로 쓴다.
- 로컬 클론 탐색: remote로 찾는다 — **정본 `EleninJayTech/claude-dev` 우선, 배포본 `EleninJayTech/claude`는 폴백**(배포본은 릴리즈 시점 상태라 정본의 미푸시 개정이 없다). 경로는 PC마다 다르니 폴더 이름·고정 경로로 믿지 말 것. 없으면 사용자에게 경로를 묻고,
  그것도 없으면 GitHub API(`https://api.github.com/repos/EleninJayTech/claude/contents/`)에서 파일 목록·download_url을 얻어 원격 조회(한글 파일명 인코딩 회피).
- 로컬 클론이면 점검 전 `git fetch`만 한다 — 이 스킬은 읽기 전용이라 `pull`은 하지 않는다(사용자가 그 클론에서 편집 중일 수 있다).
  **fetch 뒤 비교 기준은 워킹트리가 아니라 `origin/main`이다**(`git show origin/main:<파일>`) — fetch만 하고 워킹트리를 읽으면 뒤처진 파일로 비교해 "최신" 오보가 그대로 난다.
  behind 커밋 수를 병기하고, **behind > 0이면 §4의 "최신 — 조치 불요" 판정을 쓰지 않는다**(클론 워킹트리가 낡았다는 사실을 먼저 보고 + "`/dropin-update`로 클론 최신화" 권고).
- **오프라인이고 로컬 클론도 없으면**(원격 조회 실패) "점검 불가"로 보고하고 종료한다 — 추측 비교 금지.
- 각 드롭인 문서(`NN_*.md` 전부, 현재 00~06)의 **최상단 헤더+버전 표만** 읽어 `문서 버전: vX.Y`와 §4 인용 재료(해당 버전 행)를 추출한다(전체 Read 금지). 읽는 범위는 줄 수 상수가 아니라 **버전 표가 끝나는 줄까지**(`※ 갱신 시:` 직전) — 표는 개정마다 자라므로 고정 상수를 쓰면 최신 행부터 잘려 "차이 있음, 내용 미상"이 된다.

## 2) 적용 기록 점검 — 대상 프로젝트
- 대상(현재 PWD 프로젝트)의 `CLAUDE.md`(루트 또는 `.claude/`) 맨 아래 `<!-- dropin-applied` 로 시작하는 줄 파싱: 적용일·모드·문서별 버전·미선택·출처(있으면 — **`프로필=`과 조치 대기 메모는 글로벌 줄이 정본**이라 프로젝트 줄에 없는 것이 정상이다). **`dropin-applied` 뒤에 괄호 한정자가 붙을 수 있다**(예: `dropin-applied(글로벌 · 머신=YOGASLIM7):` — 00 §A STEP 5) — `dropin-applied:` 리터럴로만 찾으면 그런 줄을 "기록 없음"으로 오판한다.
- **통합 워크스페이스**(상위 폴더 아래 독립 repo 여러 개)면 루트와 하위 repo **각각**의 CLAUDE.md 기록을 점검한다(resume/wrap과 같은 패턴 — 루트 레이어분은 루트, repo 적용분은 각 repo). 하위 단위 기록의 **위임 표기**(`02·05·06은 루트 CLAUDE.md 기록 참조` 식 — 00 STEP 5)는 그 단위의 미적용으로 치지 않는다 — 해당 문서는 루트 기록 기준으로 판정한다. **단 위임 대상 루트의 실물·기록이 없으면**(그 하위 repo만 클론한 팀원) 그 문서는 **확인 불가**로 보고한다(00 §A STEP 5 — 정본 없는 위임을 "적용됨"으로 두면 영영 설치되지 않는다).
- **`~/.claude/CLAUDE.md`의 기록도 항상 함께 파싱**해(조건을 걸지 않는다 — 프로젝트 전용 설치에서도 조치 대기·`프로필=`·요금제·계정 게이트 차단은 글로벌 줄에만 있어, 조건부로 읽으면 §4가 통째로 비어 "조치 불요"가 나온다) 스코프별로 나란히 보고한다. 00 v1.12+는 프로젝트 설치에 글로벌분이 있으면 **양쪽에 병기**하므로, 글로벌 줄을 "글로벌 전용 설치"일 때만 읽으면 가장 흔한 경우를 통째로 놓친다(프로젝트 기록만 최신이고 글로벌 기록이 6개 버전 낡아도 "최신 — 조치 불요"가 나온다. 2026-08-12 실사례).
- 기록이 없으면: "적용 기록 없음(미적용이거나 2026-08-04(기록 도입) 이전 적용)"으로 보고하고 문서 비교는 생략.
- 흔적으로 추정할 때(기록 없음·02 적용 범위 확인): `.claude/agents/` 로스터만 보지 말고 rubric·핸드오프 산출물(`docs/난이도-매트릭스.md`·핸드오프 규약 문서·`docs/spec/<module>.md`·`docs/survey/<area>.md` — 목록은 여기 열거하지 않는다(선택지가 늘 때마다 낡는다, R14): **02 STEP 3의 선택 목록이 정본**이니 그 문서를 열어 각 항목의 산출물과 대조한다. **핸드오프 문서는 프로젝트마다 이름이 다를 수 있으니 기록 괄호의 `핸드오프=` 값을 먼저 보고, 없으면 `docs/`에서 규약 성격 문서를 찾는다** — 02 v1.20)과 `.gitignore`·`.git/info/exclude`도 조회 — 02 산출물은 전부 로컬 전용일 수 있어 파일 부재≠미적용(2026-08-10 오판 실사례). **`~/.claude/agents/`(개인 스코프)도 함께 본다** — 02 v1.17이 개인 배치를 허용하므로 프로젝트 경로만 보면 "미적용"으로 오판해 중복 로스터를 만들고, 개인 쪽이 이기므로 새로 만든 게 실행조차 안 된다.

## 3) 글로벌 구성 대조 — **정본 저장소 클론이 있을 때만 수행하는 절이다**
- 🔴 **먼저 게이트**: 이 절은 **remote가 `EleninJayTech/claude-dev`(정본·비공개)인 클론**이 있을 때만 도는 **유지보수자 전용** 절이고, `global-config/` 미러는 **설치 소스가 아니다**(R38 — 배포 저장소 하나로 같은 결과가 나와야 한다). `global-config/` 미러는 그 저장소에만 있고 **배포 저장소(`EleninJayTech/claude`)에는 `skills/dropin-check`·`dropin-update` 둘뿐**이다. 배포본 클론을 미러로 삼아 대조하면 사용자의 정상적인 `CLAUDE.md`·`settings.json`·스킬 전부가 **"백업에 없음"으로 무더기 오보**된다(2026-09-10 실제 신고). **폴더 이름·경로로 판별하지 않는다**(remote로만).
- **정본 클론이 없으면**(배포본만 있거나 클론이 없으면) 이 절은 **"해당 없음 — 미러 대조는 정본 저장소 유지보수용"** 한 줄로 보고하고 건너뛴다. 결함이 아니라 **일반 설치의 정상 상태**이므로 권고 목록에 올리지 않는다. §1의 GitHub API 폴백은 드롭인 문서의 헤더·버전 표만을 위한 것이라 `global-config/` 전문 대조를 대신하지 못한다. 추측 비교 금지.
- 화이트리스트 정본은 정본 저장소의 `global-config/README.md` 표다. **그 파일도 배포되지 않으므로** 위 게이트를 통과한 경우에만 참조한다.
- 대조 대상: `~/.claude`의 `CLAUDE.md`·`settings.json`·`skills/`·`commands/`·`output-styles/`를 정본 저장소 `global-config/`와 파일 단위로(없음/내용 다름).
- `settings.json`은 **구성 성격 키(`permissions.deny`·`hooks`·`attribution`·`autoMemoryEnabled`)의 차이만** 보고한다 —
  그 밖은 전부 머신 종속이라 달라도 정상(model·theme·outputStyle·enabledPlugins·statusLine·effortLevel·autoUpdatesChannel·
  마켓플레이스 소스 형식 등, DEC-20260721-bsjeong87-02). 괄호는 예시이므로 **제외 목록을 늘리지 말고 포함 기준으로 판정**한다.
- **글로벌 `CLAUDE.md`의 `dropin-applied`로 시작하는 줄은 차이로 치지 않는다** — PC별 적용 기록이라 갈라져 있는 것이 정상이다(00 §A STEP 5 · DEC-20260812-bsjeong87-11). 이 예외가 없으면 미러와 정본의 **유일한 차이가 그 줄일 때도** "내용 다름"으로 보고돼, 사용자가 남의 PC 기록을 덮어쓰게 된다.
- **줄바꿈을 정규화한 뒤 비교** — 저장소에 EOL 지시(`.gitattributes`의 `text`/`eol`)가 없으면 워킹트리 줄바꿈이 그 PC의 `core.autocrlf` 설정에 좌우돼, 내용이 같아도 파일 해시가 갈린다(대표적으로 Claude Code가 LF로 쓰는 `settings.json` ↔ CRLF로 체크아웃된 사본). 줄바꿈만 다르면 차이로 치지 않는다.
- 어느 쪽이 최신인지 단정하지 말 것 — 백업 규칙상 원본(`~/.claude`) 수정이 백업에 자동 반영되지 않으므로, 차이의 방향(로컬이 구버전 / 백업이 구버전)을 파일 내용으로 판단해 명시.
- **중복 등록 감지**: `commands/<이름>.md`와 `skills/<이름>/`이 같은 이름이면 "구형 잔재 — `/` 자동완성 2개·구형 내용 실행 위험, commands 쪽 삭제 권고"로 보고(정본은 skills, DEC-20260810-bsjeong87-04). 프로젝트 `.claude/commands/`↔`.claude/skills/`도 동일 점검.
- **런타임 관측**(파일이 아니라 **지금 도는 것**): `claude plugin list`로 설치 플러그인과 버전을 얻어 적용 기록의 03 §1 괄호(예: `claude-hud v0.8.0`)와 대조하고 뒤처짐을 한 줄 보고한다. 파일 대조만으로는 **설치본이 몇 버전인지**를 아무도 묻지 않아, 7주 낙후 플러그인이 우연히 드러난 실사례가 있다(2026-08-28). 명령이 없거나 실패하면 "미확인"으로 적는다(통과로 치지 않는다).
- **프로젝트 구성 그림자 감지**: 프로젝트에 커밋된 `.claude/skills/`·`.claude/agents/`의 동명이 개인 스코프(`~/.claude/skills/`·`~/.claude/agents/`)에도 있으면 **"개인 쪽에 가려짐"으로 보고**하고 §4 권고에 "01 §F-2 기준으로 **글로벌 동명을 그 내용으로 교체(또는 제거)**"를 붙인다(enterprise > personal > project) — 팀이 커밋한 구성이 이 PC에서 실행되지 않는 상태는 설치자 고지만으로는 영영 안 드러난다.

## 4) 보고 (표 + 증거, 변경 없음)
- 문서별: `적용 vX.Y → 현재 vX.Z` + 차이 한 줄(현재 문서 버전 표의 해당 행 인용). 미선택 문서·부분 적용 괄호 메모·**"사용자 조치 대기"·`게이트 차단(사유)`·`소스없음(사유)`/`확보 실패(사유)`** 항목도 표시한다(뒤의 셋은 재시도·재확인 대상이라 단순 "미선택"과 구분해 보고한다)(차단 기록은 "미선택"과 달리 **재확인 대상** — 조직 승인·요금제 같은 조건이 바뀌었으면 00 재적용으로 다시 묻게 안내). **기록 버전이 현재 문서 버전보다 높으면** 소스가 낡은 것이므로 그 사실을 먼저 보고한다(전진 방향만 가정하지 않는다). **기록 버전이 병합 요약 행(`vA~vB` — 버전 표 병합으로 생기며 표의 첫 행이다)의 구간 안이면** 그 구간의 행별 차이는 이미 요약돼 인용할 수 없다 — `"vA~vB 구간 요약만 가능, 상세는 정본 git 이력"` 경고를 붙여 보고한다(그 구간분이 조용히 사라지는 것을 막는 유일한 장치다).
- 글로벌: 항목별 일치/차이 목록(예: `skills/resume` 내용 다름 — 백업엔 pull-first 있음, 로컬은 구버전).
- 마지막 줄 권고: 문서 차이 → "로컬 문서 사본이 구버전이면 `/dropin-update`로 먼저 갱신 → 00 문서 재적용(재적용 분기가 버전 diff를 안내)" / 글로벌 차이 → **§3을 돌린 경우에만**(개발 저장소 클론 보유 — 일반 설치는 §3이 "해당 없음"이라 이 분기가 없다) **판단한 방향대로 2분기**: 로컬(`~/.claude`)이 구버전이면 "개발 저장소 `global-config/`에서 해당 파일 복사", 백업이 구버전이면 "원본을 그 `global-config/`로 복사해 백업 갱신·커밋"(최신 로컬을 구백업으로 덮지 않는다). **복사를 담당하는 전용 스킬은 없다** — 이 스킬은 읽기 전용이고 `/dropin-update`는 문서 파일만 다루므로, **실행 가능한 복사 명령을 그대로 제시**하고 실행은 사용자에게 맡긴다(`Copy-Item <원본> <대상> -Force` 형태로 방향까지 확정해 적어 준다. 실행 후 `/wrap`의 미러 대조가 해시로 확인해 준다). **이 스킬이 직접 복사·삭제하지 않는다** — 읽기 전용 계약(맨 위 "변경 금지")이 우선이고, §3의 방향 판정이 틀렸을 때 최신 로컬을 구백업으로 덮는 사고를 스스로 저지르지 않기 위해서다. `commands`↔`skills` 이름 중복도 같은 방식(삭제 명령 제시까지) / 적용 기록 없음 → "00 재적용으로 기록 수립 권장"(흔적 감지 한계 해소) / 전부 일치 → "최신 — 조치 불요". **단 §3을 건너뛴 경우(로컬 클론 없음)엔 "최신" 판정을 쓰지 않는다** — "문서만 최신, 글로벌 구성은 대조 불가"로 보고한다. §1의 `behind > 0` 가드와 같은 이유다: 보지 않은 축을 "이상 없음"에 포함시키면, 이 스킬이 잡으려던 글로벌 방치(§2 실사례)가 정확히 그 경로로 다시 통과한다.
