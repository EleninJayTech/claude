# kr-ui-styles — 한국 서비스 디자인 스타일 팩

kr-ui-guide가 **제약·관습**을 맡고, 이 스킬은 그 위에 얹는 **방향**을 맡는다. 팩은 리서치에서 추린 설계 기준이며 사례 브랜드를 베끼는 도구가 아니다.

## 우선순위
1. kr-ui-guide "반드시 지키는 기준" — 어떤 팩도 이기지 못한다.
2. 프로젝트의 디자인 시스템·토큰.
3. 지정된 팩의 값(`references/<팩>.md` · `references/<팩>.tokens.json`).
4. kr-ui-guide 【기본값】.
팩이 지정돼 있으면 `frontend-design`(별칭이면 그 이름)은 팩 안에서만 변주한다.

## 순서
0. 프로젝트 `CLAUDE.md` `## kr-ui-guide 오버라이드` 절의 `스타일 팩:` 값을 읽는다.
   - 값이 `없음`이거나 비어 있고 사용자가 스타일을 묻지 않았으면 **여기서 끝낸다** — 아무 파일도 읽지 않는다.
   - 사용자가 스타일을 물었으면 `${CLAUDE_SKILL_DIR}/references/catalog.md`로 팩을 보여 주고, 고르면 그 줄에 쓰자고 제안한다(승인 후에만 쓴다).
1. kr-ui-guide를 함께 적용한다(이 세션에서 아직 안 불렸으면 부른다 — 별칭이면 그 이름).
2. `${CLAUDE_SKILL_DIR}/references/<팩>.md`와 `${CLAUDE_SKILL_DIR}/references/<팩>.tokens.json`을 읽는다. 팩에 없는 값은 지어내지 않고 kr-ui-guide 【기본값】을 쓴다. 팩 토큰에 `<프로젝트별 지정 필수>`가 남아 있으면 작업 전에 묻는다.
3. `${CLAUDE_SKILL_DIR}/references/source/<팩>-report.md`는 평소 읽지 않는다 — 근거가 필요할 때 해당 `## ` 절만 찾아 읽는다.
4. 결과물을 kr-ui-guide `checklist.md`와 팩의 「팩 점검」 표로 자가 점검하고, 통과 못 한 항목은 이유와 함께 보고한다.

## 하지 않는 것
- 한 화면에 팩을 섞지 않는다 — 프로젝트당 팩 하나.
- 사례 브랜드의 색·로고·전용 서체·일러스트를 그대로 가져오지 않는다.
- 효과 수치(전환율·체류 시간)를 근거로 인용하지 않는다 — 원문이 미확인으로 둔 것이다.
- 팩의 「미확정」 항목을 규칙처럼 말하지 않는다.
