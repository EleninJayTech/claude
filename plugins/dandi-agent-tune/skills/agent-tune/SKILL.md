# agent-tune — 에이전트별 model·effort 배정

에이전트마다 맡은 일이 다르면 알맞은 모델과 노력 수준도 다르다. 이 스킬은 그 배정을 **근거와 함께 제안하고, 승인받은 것만** 에이전트 정의 파일에 반영한다. 세션 하나의 모델을 고르는 운용 프로필(단디 00 §C-6)과는 층이 다르다 — 프로필은 **제약으로 읽기만** 하고 바꾸지 않는다(바꾸려면 `/dropin-pick 프로필`).

| 인수 | 하는 일 | 파일을 고치나 |
|---|---|---|
| (없음) | 조사 → 질문 → 배정 제안 → 승인한 것만 적용 → 배정 기록 | 승인한 에이전트의 frontmatter + 배정 기록 |
| `점검` | 조사 + 배정 기록과 실물 대조 + 덮어쓰는 설정 경고 | 고치지 않는다 |
| `되돌리기 [에이전트…]` | 배정 기록의 `이전 값`으로 복원 | 승인한 것만 |

판단 기준은 `references/criteria.md`, 배정 기록 형식은 `references/record.md`에 있다 — 둘 다 읽고 시작한다.

## 지키는 것
- **승인 전에는 아무 파일도 고치지 않는다.** 고치는 것은 frontmatter의 `model:`·`effort:` 두 줄뿐이다 — 다른 키·본문은 손대지 않고, 에이전트를 만들거나 지우지 않으며, `isolation:`·도구도 바꾸지 않는다(구조는 사용 형태와 단디 02 로스터의 몫).
- **모델 ID·가격·effort 단계는 기억으로 쓰지 않는다.** 실행 당일 공식 문서를 조회하고 조회일과 URL을 배정 기록에 남긴다. 조회하지 못한 값은 🟡로 두고, 그 값에 기대는 판단(비용 지수 등)은 하지 않는다.
- **운용 프로필은 모델 열만 제약한다. effort는 맡은 일로만 정한다**(프로필로 갈리지 않는다 — 단디 00 §C-6).
- **품질 불변 지점은 어느 프로필·우선순위에서도 내리지 않는다** — 틀리면 하류 전체가 재작업되는 에이전트(난이도 분류·요구 확정·최종 리뷰·고난도 설계).
- 시크릿 파일(`.env`·키·인증서)과 대화 기록(`~/.claude/projects/`)은 읽지 않는다.
- 커밋·푸시하지 않는다. 바뀐 파일 목록과 커밋 안내만 한다.

## 0) 공식 사실 조회 (인수 없음일 때만)
WebFetch로(없으면 `claude-code-guide`·`web-fetch` 에이전트로) 조회해 메모한다:
1. `https://code.claude.com/docs/en/sub-agents` — frontmatter `model`·`effort` 허용값, 생략 시 동작, 우선순위와 덮어쓰는 환경변수.
2. `https://code.claude.com/docs/en/model-config` — 별칭(`opus`·`sonnet`·`haiku`·`fable`)이 오늘 가리키는 모델, 모델별 effort 단계와 기본값, `maxEffortLevel`·`availableModels`.
3. `https://platform.claude.com/docs/en/about-claude/pricing` — 모델별 입력·출력 단가($/MTok, 기본 행).
실패하면 그 사실을 알리고 계속한다 — 1·2가 없으면 제안에 쓸 값을 사용자에게 확인받고, 3이 없으면 비용 지수를 내지 않는다.

## 1) 에이전트 조사 (읽기만)
`references/criteria.md` §1의 자리를 전부 본다. 결과를 **현황표**로 보인다:

| 에이전트 | 위치 | 맡은 일 | 현재 model / effort | 도구 | 비고 |
|---|---|---|---|---|---|

- `위치`: `프로젝트`(`.claude/agents/`) · `개인`(`~/.claude/agents/` — 이 PC의 모든 프로젝트에 로드) · `플러그인`(고치지 않는다 — 갱신 때 덮인다) · `워크플로`(스크립트가 단계 모델을 정한다 — 보고만).
- 같은 이름이 프로젝트와 개인에 다 있으면 프로젝트 쪽이 이긴다 — 비고에 적는다.
- `model:`이 없으면 `(없음 — inherit)`, `effort:`가 없으면 `(없음 — 상속)`으로 적는다.
- 덮어쓰는 설정(criteria §1-⑤)이 있으면 표 위에 경고로 먼저 보인다.
- 에이전트가 하나도 없으면 그렇게 보고하고 끝낸다(에이전트를 만들지 않는다 — 단디를 쓰면 02 로스터를 안내한다).
- **`점검`이면** 배정 기록(`references/record.md` §1의 경로)과 실물을 대조해 `에이전트 | 기록 | 실물 | 갈림` 표를 내고 여기서 끝낸다(기록이 없으면 "배정 기록 없음").

## 2) 질문 — 코드로 알 수 없는 것만
먼저 조사로 추정한 **성격·판단 무게·난도**(criteria §2)를 표로 보이고 "이렇게 이해했다"고 확인받는다 — 틀린 행만 고쳐 달라고 한다. 그다음 AskUserQuestion으로 아래만 묻는다(한 번에 4문항까지 — 에이전트가 많으면 나눠 묻는다):
1. **우선순위**(한 번): `품질 우선` / `균형`(추천) / `비용 우선`. 속도는 같은 품질 위에서만 따진다.
2. **호출 빈도**(에이전트마다): `매 작업` / `자주` / `가끔` / `드묾`.
3. **최근 결과에 문제가 있던 에이전트**(다중 선택 — 없으면 건너뛴다). 고른 에이전트마다 원인: `빠뜨림·대충`(파일을 놓치거나 테스트를 안 돌림) / `몰라서 틀림`(맥락을 다 갖고도 판단이 틀림).
도구·맡은 일·현재 값처럼 정의에서 읽히는 것은 묻지 않는다.

## 3) 운용 프로필 읽기 (제약)
`references/criteria.md` §3대로 읽는다 — 글로벌 `~/.claude/CLAUDE.md`의 `dropin-applied` 줄 `프로필=`(한도 축), 프로젝트 `CLAUDE.md`의 `dropin-applied` 줄 `형태=`(사용 형태, 없으면 단일). `프로필=`이 없으면 한 문항으로 묻는다: `절약` / `표준` / `여유` / `종량`(값의 정본은 단디 00 §C-6). 여유이고 불변 에이전트에 `fable` 후보가 생기면 "요금제에 fable이 포함되나요?"를 묻는다(`/model`에서 fable을 고를 때 usage credits 동의를 요구하면 포함이 아니다).

## 4) 배정 제안
`references/criteria.md` §4·§5대로 에이전트마다 model·effort를 정하고 근거를 한 줄씩 붙인다. 두 표를 보인다:

**배정표**

| 에이전트 | 맡은 일 | 현재 model/effort | 제안 model/effort | 근거 |
|---|---|---|---|---|

**비용 경향**(단가를 조회했을 때만 — criteria §6)

| 에이전트 | 빈도 | 지수 현재 → 제안 | 비중(제안) |
|---|---|---|---|

- 표 아래에 합계 지수 현재 → 제안, "가장 많이 쓰는 에이전트" 한 줄, 그리고 "API 단가 기준 상대 지수 — 구독 한도 소모가 이에 비례한다는 공식 보장은 없다"를 적는다(종량 프로필이면 청구액의 직접 근거다).
- 제안이 현재와 같은 행은 `변경 없음`으로 둔다.

## 5) 승인 → 적용 → 검증 → 기록
1. AskUserQuestion으로 적용할 에이전트를 고르게 한다(다중 선택, 4개씩 나눠 — `변경 없음` 행은 내지 않는다). `개인` 위치 에이전트는 따로 묻고 "이 PC의 모든 프로젝트에 적용된다"를 설명에 적는다. 아무것도 고르지 않으면 파일을 고치지 않고 끝낸다.
2. 고른 파일마다 frontmatter의 `model:`·`effort:` 줄만 Edit으로 바꾼다. 줄이 없으면 frontmatter 안(`---` 사이)에서 `model:`은 `description:` 블록 다음 줄에, `effort:`는 `model:` 바로 다음 줄에 넣는다. `effort:`는 기본값과 같아도 지우지 않는다(생략하면 세션 값을 따를 수 있다). 줄바꿈 방식은 파일 그대로 두고 BOM을 넣지 않는다.
3. 검증: 고친 파일마다 frontmatter를 다시 읽어 `name`·`model`·`effort`를 출력하고, frontmatter가 `---`로 열리고 닫히는지 본다. `/agents`로 목록을 확인하라고 안내한다.
4. 배정 기록을 `references/record.md`대로 쓴다(없으면 만들고, 있으면 표를 갱신하고 이력에 한 줄 덧붙인다). 고친 에이전트의 `이전 값`을 반드시 남긴다 — `되돌리기`의 유일한 근거다.
5. 보고: 바뀐 파일 경로 목록 + "커밋은 사용자가 한다". 프로젝트 `.claude/agents/`는 커밋되면 팀 전원에게 적용된다고 알린다.

## `되돌리기`
배정 기록 표에서 대상 에이전트(인수가 없으면 전부)의 `이전 값`과 실물 현재 값을 표로 보이고, 승인받은 것만 5)의 2~4와 같이 되돌린다(`references/record.md` §3). 기록이 없으면 되돌릴 근거가 없다고 알리고 끝낸다.
