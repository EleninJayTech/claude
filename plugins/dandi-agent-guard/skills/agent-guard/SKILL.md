# agent-guard — 병렬 에이전트 상한 확인·조정

훅이 서브에이전트를 띄울 때마다 이 PC의 코어 수·메모리와 그 순간의 여유 메모리·CPU를 보고, 상한을 넘는 스폰을 거부한다. 세션 시작 때는 "지금 N개까지"를 한 줄로 알린다. 이 스킬은 그 상태를 보고 값을 바꾸는 입구다.

## 절차
1. 상태를 읽는다:
   ```
   node "${CLAUDE_SKILL_DIR}/guard.mjs" status
   ```
2. 출력의 사양 상한·지금 상한·실행 중 수를 사용자에게 한 줄로 알린다. 스폰이 거부돼 불렀다면 거부 사유(사양 상한·여유 메모리·CPU)가 무엇이었는지 함께 말한다.
3. 조정은 `~/.claude/agent-guard/config.json`으로 한다(없으면 만든다 — 사용자 확인 후). 바꾼 값은 다음 스폰부터 적용된다.

   | 키 | 기본 | 뜻 |
   |---|---|---|
   | `max` | 8 | 사양이 좋아도 이 수를 넘지 않는다 |
   | `perAgentGB` | 1 | 에이전트 하나에 잡아 두는 메모리(GB) — 브라우저·에뮬레이터를 많이 쓰면 올린다 |
   | `reserveGB` | 1.5 | 다른 프로그램 몫으로 남겨 두는 메모리(GB) |
   | `cpuHigh` | 85 | CPU 사용률이 이 값 이상이면 더 띄우지 않는다 |
   | `ttlMin` | 45 | 종료 신호를 못 받은 에이전트를 실행 중으로 세는 최대 시간(분) |
   | `off` | false | `true`면 가드를 끈다(훅은 돌지만 아무것도 막지 않는다) |
4. 실행 중 수가 실제와 다르면(세션이 비정상 종료된 뒤 등) 표식을 비운다: `node "${CLAUDE_SKILL_DIR}/guard.mjs" reset`
5. 세션 시작 때 `[agent-guard]` 안내가 없었다면 훅이 불리지 않는 것이다 — 플러그인이면 `/plugin`에서 `dandi-agent-guard`가 켜져 있는지, 사본이면 `~/.claude/settings.json`의 `hooks`에 `guard.mjs` 항목이 있는지, 공통으로 `node --version`(18 이상)을 확인하라고 알린다.

## 지키는 것
- 설정을 바꾸거나 끄는 것은 **사용자가 정한다** — 스폰이 거부됐다고 스스로 `off`로 바꾸지 않는다.
- 세션마다 1개는 항상 허용된다. 거부되면 실행 중인 에이전트가 끝난 뒤 다시 띄우거나 메인 대화에서 처리한다.
- 워크플로(`Workflow` 도구)의 에이전트는 이 훅이 막지 못한다 — 세션 시작 때 받은 상한에 맞춰 동시 실행 수를 짠다.
- 에이전트가 실제로 쓰는 메모리는 미리 알 수 없어 `perAgentGB`로 어림한다. 훅은 모델을 부르지 않고 `~/.claude/agent-guard/`에 실행 중 표식만 쓴다.
