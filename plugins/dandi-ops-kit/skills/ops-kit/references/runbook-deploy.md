# ① 배포 런북 — 첫 배포 · 재배포 · 롤백

운영자가 **처음부터 다시 배포하거나, 방금 배포한 것을 되돌릴 때** 이 문서 하나만 보고 끝낼 수 있어야 한다. 가장 자주 쓰이는 것은 재배포이고, 가장 급하게 쓰이는 것은 롤백이다.

## 진단 신호

| 판정 | 조건 |
| --- | --- |
| 필요 | 배포 명령(`deploy` 스크립트·CI 배포 단계)이나 호스팅 설정 파일(`wrangler.*`·`fly.toml`·`vercel.json`·`netlify.toml`·`render.yaml`·`Dockerfile`·`Procfile`·`app.yaml`)이 있다 |
| 불필요 | 로컬에서만 돌리는 CLI·라이브러리이고 배포 대상이 없다(패키지 레지스트리 배포만 있으면 판단 보류 — 그건 "릴리스"다) |
| 판단 보류 | 배포 대상이 보이지만 방식이 정해지지 않았다(설정 파일이 비었거나 서로 다른 호스팅 설정이 둘 이상) |

## 만들 것

`docs/status/deploy-runbook.html`(문서 id `deploy`). 절 순서:

1. **사전 확인** — 필요한 도구와 버전 확인 명령(`node -v`·CLI `--version`·로그인 상태 확인 명령), 이 문서가 다루는 대상(서비스 이름·리전·DB 이름 — 조사에서 찾은 값). 시크릿 목록은 **이름·용도·기대 길이·보관 위치**만 표로.
2. **첫 배포** — 빈 계정에서 동작하는 상태까지: 리소스 생성(DB·버킷·KV) → 설정 파일에 ID 반영 → 마이그레이션 → 시크릿 등록(SKILL.md §4 파이프+길이 형식) → 배포 → 배포 후 확인. 외부 연결(봇 웹훅 등록·도메인 연결)이 있으면 그 단계까지.
3. **재배포** — 평소 경로. 마이그레이션이 배포 명령에 포함되는지 따로 돌려야 하는지를 **실제 스크립트를 읽고** 적는다(예: `deploy` 스크립트가 마이그레이션을 먼저 돌리는지). 이것을 틀리게 적으면 스키마가 빠진 채 배포된다.
4. **롤백** — ⓐ 직전 버전을 식별하는 방법(배포 이력 명령·대시보드 위치) ⓑ 되돌리는 명령 ⓒ 되돌린 뒤 확인 ⓓ **되돌릴 수 없는 것**(이미 적용된 DB 마이그레이션·보낸 메시지·결제)과 그때 할 일. 코드 롤백이 스키마를 되돌리지 않는다는 점을 반드시 적는다.
5. **배포 후 확인** — 헬스 엔드포인트(있으면)·주요 화면·로그 확인 명령. ⑤가 있으면 그 상태 확인.

모든 단계는 SKILL.md §4의 네 칸(명령·성공 문구·실패하면·Claude에게)을 갖는다.

## 형식·템플릿

- 단계 id는 `deploy/<절 번호>-<순번>`(예: `deploy/2-4`). 보고 틀과 `<details id>`에 같은 값을 쓴다.
- 호스팅별 명령은 **작성하는 날 공식 문서로 확인**해 넣는다. 아래는 찾아볼 대상의 예일 뿐 정답이 아니다:
  - Cloudflare Workers: 배포 이력 조회와 롤백 명령(wrangler의 deployments·rollback 계열), D1 원격 마이그레이션 적용.
  - Cloudflare Pages·Vercel·Netlify: 이전 배포를 프로덕션으로 승격(대시보드·CLI).
  - Fly.io·Render: 이전 릴리스·이미지로 되돌리기.
  - 컨테이너(Docker): 이전 이미지 태그로 재기동 — 태그를 남기는 습관(배포마다 고유 태그)을 사전 확인에 넣는다.
- 확인하지 못한 명령·출력 문구에는 `[재확인]`을 붙이고 확인 방법(공식 문서 URL·`--help`)을 함께 적는다.
- 머리말 아래에 **"급할 때"** 상자 하나를 둔다: 롤백 절로 가는 링크와 그 첫 명령.

## 검증

- 런북의 모든 명령에 나오는 스크립트 이름·폴더·설정 키가 저장소에 실제로 있는지 `grep`으로 대조한다(없는 스크립트를 부르는 런북은 첫 단계에서 막힌다).
- 단계마다 네 칸이 있는지 본다: `<details class="step"` 개수와 `Claude에게` 개수가 같아야 한다.
- 시크릿 단계에 `Ctrl+V`·"붙여넣기"·"clipboard" 지시가 없고, 길이 출력(`.Length`·`${#`)이 있는지 본다.
- 시크릿 값으로 보이는 긴 무작위 문자열이 문서에 없는지 본다.
- 상태 파일 표에 ① 행을 추가·갱신한다.
