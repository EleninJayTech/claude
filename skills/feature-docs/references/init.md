# init 모드 — 최초 문서화 / 증분 추가

## 역할
이 프로젝트의 기능 명세 관리자로서, 모든 기능을 다른 AI 세션이 문서만 보고
(1) 이해하고 (2) 화면에서 재현하고 (3) 자동 테스트를 돌릴 수 있게 문서화한다.

## 모드 판단
- `docs/features/` 가 없으면 **전체 문서화**.
- 있으면 **증분**: 00_inventory.md 와 코드·화면을 대조해 누락 기능만 추가한다.
  기존 문서는 건드리지 않는다 (기존 문서 갱신은 sync 의 일).
- 00_inventory.md 의 상태 열에 "작성중" 이 남아 있으면 이전 세션이 중단된 것이다.
  그 지점부터 이어서 한다.

## 절차

### 0단계: 프로젝트 탐지
SKILL.md 의 "0. 프로젝트 자동 탐지" 를 수행하고 결과를 `docs/features/PROJECT.md`
에 저장한다 (형식은 template.md).

### 1단계: 기능 인벤토리 → 멈추고 승인
1. 코드에서 기능 목록을 뽑는다. 보는 곳: 라우터/라우트 정의, 컨트롤러, 네비게이션·메뉴
   정의, 화면 컴포넌트 폴더, AndroidManifest 의 Activity, iOS Storyboard/SwiftUI 뷰,
   API 엔드포인트 목록.
2. 실제 화면에서 메뉴·네비게이션을 순회하며 목록과 대조한다.
3. `docs/features/00_inventory.md` 에 표로 쓴다:
   `기능ID | 기능명 | 플랫폼 | 진입경로 | 담당 코드 위치 | 상태`
   기능ID 는 F-001 부터 순번. 증분 모드면 기존 마지막 번호 다음부터.
4. **여기서 멈추고** 사용자에게 인벤토리를 보여준다. 승인·수정을 받은 뒤 2단계로 간다.
   기능이 50개를 넘으면 2단계를 여러 세션으로 나누자고 제안한다.

### 2단계: 기능별 문서 작성
- 인벤토리 순서대로 기능 하나 = 파일 하나 (`F-001_로그인.md`). template.md 의 템플릿을
  그대로 따른다.
- 기능마다: 코드 읽기 → 화면에서 실제 조작 → 스크린샷 저장 → 테스트 케이스 작성 →
  frontmatter 버전 필드 채우기 → 인벤토리 상태 열 갱신.
- 10개 단위로 사용자에게 진행 상황을 보고하고 이어간다.
- 컨텍스트가 부족해지면 진행 중인 기능의 인벤토리 상태를 "작성중" 으로 두고 멈춘다.
  사용자에게 "새 세션에서 `/feature-docs init` 을 다시 실행하면 이어서 한다" 고 알린다.

### 3단계: 통합 문서와 CLAUDE.md
- `VERSION.md` (template.md 형식)
- `01_screen_flow.md`: 화면 이동 관계를 mermaid 로
- `02_data_model.md`: 기능이 다루는 주요 데이터와 상태
- `03_test_index.md`: 전체 TC ID 목록, 권장 실행 순서, 케이스 간 의존성
  (예: 로그인 TC 가 실패하면 차단되는 케이스)
- 프로젝트 루트 CLAUDE.md 에 template.md 의 "기능 문서 유지 규칙" 을 추가한다.
- 정기 무인 테스트를 원하면 문서의 테스트 케이스를 Playwright(웹) / Maestro(앱)
  스크립트로 변환하는 단계를 제안하고, 만들면 PROJECT.md 의 "테스트 스크립트" 에 경로를 적는다.
  (`/feature-test` 가 이 경로를 우선 실행한다)
