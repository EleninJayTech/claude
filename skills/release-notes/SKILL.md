# release-notes

## 범위
- `$0` = 시작, `$1` = 끝(기본 HEAD). `$0` 이 없으면 `git describe --tags --abbrev=0` 로
  최신 태그를 시작으로 잡고 사용자에게 확인한다. 태그가 하나도 없으면 커밋 해시나 날짜를 묻는다.

## 자료 수집
1. **기능 문서 변경 이력** — 각 `F-xxx_*.md` 의 "변경 이력" 표에서 커밋 열이 구간 안에
   드는 행. `git merge-base --is-ancestor` 또는 `git log 시작..끝 --format=%h` 목록과 대조한다.
   status 가 폐기로 바뀐 기능도 잡는다.
2. **VERSION.md history** — 구간 내 행. 앱 버전 변경 시점을 확인한다.
3. **git log** — `git log 시작..끝 --oneline --no-merges`. 문서 이력에 없는 커밋은
   "문서 미반영" 으로 따로 모은다 (릴리스 노트에는 넣되, `/feature-docs sync` 필요를 보고).
4. **테스트 리포트** — `docs/features/test_reports/` 에 구간 내 리포트가 있으면 마지막 결과 요약을 가져온다.

## 작성 규칙
- 기능 단위로 묶는다. 커밋 나열이 아니다. 같은 기능의 여러 커밋은 한 항목으로 합친다.
- 분류: **신규 기능 / 변경 / 수정 / 제거(폐기)**. 문서 변경 이력의 문구를 기준으로 하고,
  판단이 안 되면 "변경" 에 넣는다.
- 문장은 명사형으로 끝낸다 ("로그인 실패 시 오류 메시지 표시" / "결제 취소 기능 추가").
- 사용자 관점으로 쓴다. 내부 리팩터링·의존성 업데이트는 "내부 변경" 한 줄로 요약한다.
- 문서에 없는 사실을 지어내지 않는다. 커밋 메시지만으로 불분명하면 diff 를 보고, 그래도
  모르면 "[확인 필요]" 를 붙인다.

## 출력
`docs/releases/<끝 태그 또는 날짜>.md` 로 저장하고 채팅에도 출력한다.

```markdown
# 릴리스 노트 v1.3.0 (2026-09-08)
구간: v1.2.0 (abc1234) → v1.3.0 (def5678) · 앱 버전 1.2.0 → 1.3.0 · docs_version 3.2 → 4.0
```
