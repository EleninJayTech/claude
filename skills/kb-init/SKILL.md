# /kb-init — 마크다운 지식 베이스 만들기

정보를 던지면 Claude가 분류해 저장하고, 물으면 찾아 답하는 기록 저장소를 빈 폴더에 한 벌 만든다. 만드는 일은 동봉 스크립트가 한다(결과가 매번 같고 토큰을 쓰지 않는다). 이 스킬은 묻고, 미리 보이고, 보고한다. 만든 저장소는 `/kb-dashboard`가 설정 없이 바로 읽는다.

스크립트는 `${CLAUDE_SKILL_DIR}/scripts/kb-init.mjs`, 템플릿은 `${CLAUDE_SKILL_DIR}/templates/`다.

## 지키는 것
- **있는 파일은 덮지도 합치지도 않는다.** 루트에 `CLAUDE.md`나 `.claude/kb-dashboard.json`이 있으면 스크립트가 거부한다 — 우회하지 않는다.
- **소프트웨어 프로젝트 폴더 안에 만들지 않는다.** 소스·빌드 파일이 보이면 멈추고 새 폴더를 권한다(지식 베이스의 `CLAUDE.md`는 저장소 전체 규칙이 된다).
- **원격 저장소를 만들거나 push하지 않는다.** `git init`과 첫 커밋만, 그것도 물은 뒤에 한다.
- 템플릿을 손으로 옮겨 쓰지 않는다. Node.js 18 이상이 없으면(`node --version`) 멈추고 그 사실만 알린다.
- 비밀번호·토큰·회사 기밀 원문을 넣는 저장소가 아니라는 점을 끝에 한 줄로 알린다(생성된 `CLAUDE.md` 「비밀 정보」 절).

## 1. 위치 확인
1. 인수가 있으면 그 경로, 없으면 현재 폴더를 루트로 삼는다. 폴더가 없으면 만들지 묻는다.
2. 루트를 2단계까지 본다(본문은 읽지 않는다).
   - `.claude/kb-dashboard.json`이 있다 → 이미 지식 베이스다. `/kb-dashboard 점검`을 안내하고 멈춘다.
   - 루트 `CLAUDE.md`가 있다 → 멈춘다. 분류 표가 이미 있는 저장소면 `/kb-dashboard 설정`을, 아니면 새 폴더를 권한다.
   - 소스·빌드 파일(`package.json`·`pubspec.yaml`·`src/` 등)이 있다 → 멈추고 새 폴더를 권한다.
   - 그 밖의 파일이 있다 → 무엇이 있는지 알리고 계속할지 묻는다(있는 파일은 건드리지 않는다).

## 2. 묻기 (한 번에)
언어는 묻지 않고 정한다 — `~/.claude/CLAUDE.md`의 `dropin-applied` 줄에 `언어=`가 있으면 그 값, 없으면 지금 대화 언어(`ko` 또는 `en`).

AskUserQuestion 한 번으로 묻는다. 선택지마다 고르면 생기는 것을 한 줄로 붙인다.
1. **구성 형태** — `한 폴더`(추천: 루트가 곧 기록 폴더. 한 PC·한 용도) / `회사·개인 분리`(`work/`·`home/`과 공용 `common/`. PC마다 한쪽만 받아 쓸 수 있다). 다른 이름을 원하면 폴더 이름과 성격(회사/개인)을 받는다.
2. **기록 타입** — `기본 세트`(추천: 회의·프로젝트·이슈·절차·프롬프트·성과·팁·참고) / `가볍게`(절차·팁·참고). 직접 고르면 그 목록을 받는다. 타입은 만든 뒤에도 늘리고 줄일 수 있다(생성된 `CLAUDE.md` 「타입 개정」).
3. **함께 만들 파일**(다중 선택, 둘 다 기본) — `할일 파일`(상태를 추적하는 한 줄 목록) / `아티팩트 링크 파일`(게시한 페이지 주소 기록).
4. **git** — 루트가 git 저장소가 아닐 때만: `git init 한다`(추천) / `하지 않는다`.

이어서 이름 충돌을 본다 — `~/.claude/skills/`의 `log`·`find`·`todo`·`report` 폴더와 `~/.claude/commands/`의 같은 이름 `.md`. 하나라도 있으면 알리고(개인 스코프가 프로젝트 스킬을 가린다) 접두사 `kb-`를 붙일지 묻는다.

## 3. 미리 보기
답을 JSON으로 OS 임시 폴더에 쓴다(저장소 안에 두지 않는다).

```json
{
  "lang": "ko",
  "targets": [{ "dir": "work", "kind": "work" }, { "dir": "home", "kind": "personal" }],
  "shared": "common",
  "types": ["meeting", "project", "issue", "howto", "prompt", "achievement", "tip", "reference"],
  "todo": true,
  "artifacts": true,
  "commandPrefix": "",
  "dashboardCmd": "/kb-dashboard"
}
```

- `한 폴더`면 `targets`는 `[]`, `shared`는 뺀다. `가볍게`면 `types`는 `["howto", "tip", "reference"]`.
- `dashboardCmd`에는 이 PC에서 실제로 부르는 대시보드 스킬 이름을 넣는다(별칭·플러그인이면 그 이름). 대시보드 스킬이 없으면 기본값을 두고 마지막 보고에서 설치를 안내한다.

```
node "${CLAUDE_SKILL_DIR}/scripts/kb-init.mjs" plan --root "<루트>" --answers "<답 파일>"
```
`CREATE`·`EXISTS` 목록을 폴더별로 묶어 보이고 진행할지 확인받는다. `EXISTS`는 건드리지 않는 파일이라고 밝힌다.

## 4. 만들기
```
node "${CLAUDE_SKILL_DIR}/scripts/kb-init.mjs" apply --root "<루트>" --answers "<답 파일>"
```
출력 한 줄(`OK <루트> created=… skipped=…`)을 그대로 보고하고 답 파일을 지운다.

git을 고른 경우에만: `git init` → 만든 파일만 `git add` → 커밋할지 묻고, 하겠다고 하면 `docs: 지식 베이스 초기 구성` 한 번. 원격 연결은 안내만 한다 — 비공개 저장소를 권하고, 회사 기록이 들어갈 저장소면 조직 정책을 먼저 확인하라고 알린다.

## 5. 마무리 보고
- 만든 것 요약(폴더·타입·스킬 이름)과 **그 폴더에서 새 세션을 열어야 프로젝트 스킬이 뜬다**는 점.
- 쓰는 법 네 줄: 기록 `/log <내용>` · 검색 `/find <질문>` · 할일 `/todo` · 산출물 `/report <주제>`(접두사를 붙였으면 그 이름).
- 한눈에 보기: `/kb-dashboard`(설정 파일을 이미 만들어 두었다).
- 대상을 나눴으면 생성된 `README.md`의 「여러 PC에서 쓰기」 절을 가리킨다.
- PC마다 다른 값은 `CLAUDE.local.md`(예시 파일을 복사)에 둔다. 비밀번호·토큰은 어디에도 쓰지 않는다.

## 오류일 때
스크립트는 답·대상 폴더 오류면 종료 코드 2와 사유 한 줄을 낸다. 그 줄을 그대로 전한다. 스크립트나 템플릿을 고쳐 쓰지 않는다.
