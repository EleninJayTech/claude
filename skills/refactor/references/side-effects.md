# 사이드 이펙트 체크리스트

리팩터링한 변경 하나마다 아래를 수행하고, 항목별로 **통과 / 실패 / 미검증(사유)** 를 남긴다.
"해당 없음" 도 판단 근거와 함께 적는다. 결과가 없는 항목은 통과가 아니다.

## A. 호출처 (변경한 심볼마다)
검색 대상 — 코드만 보면 놓친다:
- 소스: 직접 호출, 오버라이드, 인터페이스 구현, 데코레이터·어노테이션 참조
- 문자열: 리플렉션(`getattr`, `Class.forName`, `method_missing`), 이벤트 이름, 라우트 이름, 직렬화 키
- 템플릿: HTML/JSP/Thymeleaf/Vue 템플릿 안의 메서드·프로퍼티명
- 설정: DI 컨테이너(XML/yaml/json), 스케줄러, 큐 컨슈머 등록, ORM 매핑, API 스펙(OpenAPI)
- 테스트·목(mock): 목 객체가 옛 시그니처를 가정하는지
- 스크립트·문서: 마이그레이션, CLI 진입점, README 의 예제 코드, `docs/features/` 코드 참조
- 외부: 다른 저장소·서비스가 이 코드를 호출하는지 (public 패키지, API 엔드포인트). 확인 불가면 미검증.

검색은 단어 경계(`\bname\b`)로, 대소문자 변형과 케밥/스네이크 변형도 함께.

## B. 계약
변경 전후로 같은가:
- 인자 개수·순서·기본값·타입, 가변 인자
- 반환 타입과 값 — 특히 `null`/빈 컬렉션/`Optional`/예외 중 무엇을 돌려주는지
- 던지는 예외 종류와 조건
- 호출 순서 의존 (A 다음 B 를 불러야 하는 것), 멱등성
- 부수효과: 로그, 메트릭, 이벤트 발행, 캐시 갱신, 파일·DB 쓰기 — 통합하면서 한쪽 부수효과가 사라지지 않았는지
- 동시성: 락 범위, 스레드 안전성, 정적/전역 상태

## C. 데이터·외부 형식
- 직렬화 결과(JSON 키·순서·null 표현), DB 스키마·쿼리 결과 컬럼, 파일 포맷, 로그 포맷
- 날짜·시간대·로케일·문자 인코딩 처리
- 숫자: 정수/실수, 반올림, 오버플로

## D. 실행 검증
1. 기준선 테스트 재실행 → 새로 실패한 것만 문제. 기존 실패는 별도 표기.
2. 테스트가 없던 코드: 리팩터링 **전** 출력을 먼저 기록하고 **후** 와 비교하는 특성화 테스트.
   대표 입력 3개 이상 (정상 / 경계값·빈값 / 오류). 테스트 파일로 남긴다.
3. `docs/features/` 가 있으면 영향 기능 `/feature-test F-xxx` 실행.
4. 빌드·타입체크·린트 깨끗한지. 경고가 늘지 않았는지.
5. 실행이 필요한 항목(실제 DB, 외부 API, 배치·스케줄러)은 로컬에서 돌려보고, 못 하면 미검증.

## E. 되돌리기
- 변경 하나가 커밋 하나로 되돌릴 수 있는 단위인지
- 되돌릴 때 데이터 마이그레이션이 필요한 변경은 없는지 (있으면 리팩터링 범위 밖 — 보고)
