# /audit — 내부 정합성 전수조사 (이 repo 전용)

**/reverify와의 역할 구분**: /reverify = 바깥 세계 대비 최신성(공식 문서 당일 조회). **/audit = 우리 문서끼리의 내부 결함**(서로 어긋남·빠진 케이스·드리프트) — 인터넷 조회 없이 저장소·글로벌 구성만 읽는다.
**권장 시점**: 개정이 몰린 뒤(하루 3버전+ 승급 등), 또는 분기 1회. 실사례 결함 유형이 늘면 아래 렌즈에 추가한다.

## 0. 준비
- `git status` — 미커밋 있으면 먼저 보고. `CLAUDE.md` 구성물 표에서 현재 문서 목록·기대 버전 파악(문서가 늘었으면 아래 범위에 자동 포함).
- 조사·재검증 전 과정 **읽기 전용** — 수정은 §4 승인 후에만.

## 1. 조사 (백그라운드 에이전트 렌즈별 병렬(아래 전부) — 전부 도착한 뒤 §2로)
각 에이전트에 공통 지시: 읽기 전용 / 발견마다 `[심각도 상·중·하] 파일:줄 — 문제 / 근거(원문 인용) / 실해 시나리오 / 제안 한 줄` / 확신 없으면 `[의심]` 표기 / **의도된 설계는 보고 제외**(md 단일 관리, 사람용 페이지 독립 산출물, 드롭인 얇게(A안), 절약 프로필의 품질 불변 지점, 조건부 최소 안내 원칙, 무단 덮어쓰기 금지라 강제 업데이트 없음, §F-2 템플릿이 실제 스킬보다 짧은 요약인 것 자체).

- **A. 규칙 정합성** — 00·01·repo CLAUDE.md·글로벌 스킬 4종(resume·wrap·dropin-check·dropin-update): ① 규칙 A의 전제를 규칙 B가 바꿨는데 A 미갱신(예: "포인터 맨 아래" vs "/resume 40줄 읽기" — 2026-08-12 실사례) ② 같은 규칙의 사본 3벌(01 §F-1·§F-2 ↔ repo CLAUDE.md ↔ 실제 스킬) 간 드리프트 ③ 절차 순서·조건 모순.
- **B. 버전·참조 무결성** — 전 문서(00~) + CLAUDE.md·README + 사람용 페이지 표기: ① 헤더↔푸터 버전·날짜 일치 ② 버전 표 시간순·결번 ③ CLAUDE.md 구성물 표 ↔ 실제 헤더 전수 대조 ④ 문서 간 §참조가 실재하는 섹션인지 ⑤ 파일명·raw URL·스킬 이름 실재 ⑥ 예시 속 버전 하드코딩 재발(vX.Y 플레이스홀더 위반 — DEC-20260810-bsjeong87-07).
- **C. 절차 케이스 누락** — 00·01·02·글로벌 스킬 4종에 사용자 여정 대입: 신규 설치(대상 2×확보 경로 3: 사본·클론·raw), 재적용(기록 유/무·출처 유/무·부분 완료 메모), 특수 환경(비-git·오프라인·더티 트리·push 권한 없음), 02 여정(부분 선택·자체 에이전트 기존재), 회사 게이트 "아니오" 이후, 스킬 간 핸드오프(check 보고 후 다음 행동), 통합 워크스페이스/MSA에서 기록·점검 레벨. 정의 안 된 분기·막다른 길을 찾는다(예: 클론 참조 설치를 update가 모름 — 2026-08-12 실사례).
- **D. 저빈도 문서 정밀** — 직전 audit/집중 점검에서 덜 본 문서(기본 04·05·06, 상황 따라 조정): 실행 프로토콜 완결성(감지→질문→설치→검증(증거)→기록), 00 §B·§C·STEP 2가 그 문서에 대해 주장하는 것과 본문 일치, 게이트·스코프·검증 명령의 내부 모순.
- **E. 실물↔백업↔명세 3자 대조** — `~/.claude` 화이트리스트 5종 ↔ `global-config/` 파일 단위 해시(줄바꿈 차이는 내용 diff로 판별) ↔ 01 §D-2/3/4·§F-2 명세: 한쪽에만 있는 파일, 구성 성격 키(deny·hooks) 차이(머신 종속 키 차이는 정상 — DEC-20260721-bsjeong87-02), §D-4 raw URL 실재, commands↔skills 이름 중복. **시크릿 파일은 열지도 언급하지도 않는다.**
- **F. 자작 스킬 전수** — A·E가 다루는 세션 스킬 4종 외의 **자작·설치 스킬 전부**(프로젝트: reverify·audit 등 `.claude/skills/` / 글로벌: skill-setup(`~/.claude/commands/`)·humanizer(외부 저작 설치본 — 내용 검증은 제외, 참조·frontmatter 정합만) 등 — 인벤토리는 실물 폴더 `skills/`+`commands/`에서 나열): ① 스킬이 인용하는 §번호·DEC·파일 경로·문서 번호 범위가 실물과 일치하는지 하나씩 확인 ② 스킬 절차가 이후 도입된 규칙(출처= 필드·포인터 최상단·40줄 읽기 등)과 어긋나는 단계 ③ frontmatter 정합(name↔폴더, disable-model-invocation — 관리자 전용이 자동 호출로 열려 있으면 문제, **첫 3바이트가 `2d 2d 2d`인지**(UTF-8 BOM `ef bb bf` 금지 — BOM이 붙으면 `---`가 인식되지 않아 frontmatter 전체가 description화되고 `disable-model-invocation`이 무력화된다. 2026-08-12 skill-setup 실버그)) ④ 같은 이름의 글로벌/프로젝트 중복(개인 스코프가 프로젝트를 덮어 가려짐).

## 2. 재검증 (에이전트 보고를 그대로 믿지 않는다)
발견마다 해당 원문을 직접 열어 대조 → **확정/오탐/의도된 설계** 판정. `[의심]`은 판단 근거를 명시해 확정 또는 기각. 오탐률과 함께 기록.

## 3. 보고 (수정 전 — 여기서 멈추고 승인 대기)
확정 발견만 심각도순 표: `# | 심각도 | 파일:줄 | 문제 | 실해 시나리오 | 제안`. 이상 없던 점검 축도 "이상 없음"으로 명시(무엇을 확인했는지가 증거). 오탐·기각 목록은 접어서 한 줄 요약.

## 4. 수정 (승인된 항목만)
- 경량 반영(A안) 원칙 — 한두 줄 수술적 수정. 문서 수정 시 버전 표 한 줄+bump+푸터 날짜, CLAUDE.md 표 동기화. 글로벌 스킬 수정 시 `global-config/` 미러+해시 일치 확인(**줄바꿈 정규화 기준** — CRLF/LF 차이로 오검출된다).
- 기록: PROGRESS 최상단 append, 설계 변경이면 새 DEC(날짜+작성자 발번), PROJECT_PLAN 갱신 — **"다음 내부 정합성 전수조사" 예정일을 다음 분기로 갱신**(이 항목이 /resume의 예정일 경과 안내에 걸려 다음 수행을 알려준다). 커밋·푸시(이 repo 상시 허용) 후 **증거로 보고**(수정 N건·커밋 해시·검증 출력).
